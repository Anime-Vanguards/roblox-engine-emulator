# Engine architecture and contract

This document is the technical specification for `roblox-engine-emulator` (`ree`): what each subsystem does, the Roblox Studio rules it enforces, and the file/protocol formats it consumes and produces. Update this document in the same commit whenever an interface or behavioral rule changes.

For installation and builds see [building.md](building.md), for CLI commands see [cli.md](cli.md), and for Rust embedding see [api.md](api.md).


`ree` originated as the Rust rewrite of the Luau emulator inside [roblox-ui-renderer](https://github.com/Anime-Vanguards/roblox-ui-renderer) (`rur`) and was split into its own crate in October 2026. The original Luau-in-Luau emulator spent ~97% of CPU time inside emulator overhead rather than game code; moving the core to Rust with an embedded Luau VM (`mlua`) lets unmodified game Luau interact with native `Instance` userdata just as it does in Roblox. `rur` adds GUI layout, text shaping, input, and scene export on top as a `Layer`.

## Design principles

1. **Parity first.** Everything visible to scripts matches Roblox Studio as measured (citing Studio version/date, fixture, and measurements in code comments), falling back to official Roblox documentation where not yet measured. Unemulated members never silently guess values: each reports itself (`Engine::missing`). The first use of a member writes an `Output` line of kind `missing` (`<Class.Member> is not emulated`, its trace the script position `<script path>:<line>`, read from the running Luau stack past C functions and the engine's own `rur.*`/`ree.*` chunks; none when the engine itself made the use), and every use is counted in `state.output.missing` (`(member, count)`, first-use order; `missing_first` beside it holds the first position and time). `ree run`/`ree record` summaries list them as `unemulated` ([cli.md](cli.md#the-summary)). A `missing` line is the engine's: LogService (MessageOut, GetLogHistory) never gets it and it is no error. What reports: a reflected method no behaviour implements (`lua::instance` returns nil); stubs that do nothing or answer a stand-in where a client does something a script can see (`R.Missing` in the service Luau, `services::unemulated` in Rust); and writes a client does more for than store (`lua::instance::unemulated_write`: a Humanoid's `Health` reports `Humanoid.HealthChanged` for a change, `Humanoid.Died` at 0 or below, and a value outside 0..MaxHealth; ree has no Humanoid simulation). A stub that does nothing because a client does nothing a script can see either (an unbind with nothing bound, `Player:Move` without a character, `AnalyticsService` logging, `BindToClose`) stays quiet and says why in a comment, and so do the offline player's own answers (in no group, the Async group methods as the older ones: see "Player's group methods").
2. **Speed without behavioral drift.** Hot paths access properties by pre-interned IDs (`NameId`), avoid per-frame allocations across whole scenes, and execute common `Instance` operations in C metamethods without crossing into Rust/mlua closures.

## Verification and determinism

- **`cargo test --release`:** Runs engine unit tests (`src/tests.rs`, scheduler, datatypes, world, recorder, bundles, `Emulator`), patched-VM tests (`tests/luau_vm.rs`), CLI and process-guard tests (`tests/cli.rs`), standalone release/worker tests (`tests/standalone.rs`, needs Node.js), and host compatibility tests (`tests/host_worker.rs`). Needs no Studio, GPU, game checkout, or network.
- **Vendor check (`node tools/vendor.mjs --check`):** Verifies `vendor/` equals pinned upstream archives + `patches/` ([building.md](building.md#updating-luau)).
- **Live client Luau FFlags:** The VM loads live Roblox client flags from `data/luau-flags.json` (updated via `node tools/luau-flags.mjs`, applied by `patches/luau/14-client-flags.patch` before VM startup). Override with `REE_LUAU_FLAGS=off` (keeps `LuauEmitCallFeedback` and `LuauPromoteProto` enabled under `jit`) or `REE_LUAU_FLAGS=FFlagName=true,FIntName=3`.
- **Deterministic hashing and recordings:** Tables keyed by instances, tables, functions, or threads iterate in deterministic creation order rather than memory-address order (`patches/luau/04-deterministic-hash.patch`, `REE_HASH_SEED`), guaranteeing byte-identical `scene.rbxm`, `playback.json`, `events.json`, `camera.json`, and `summary.json` across runs.
- **Downstream regression gate:** `roblox-ui-renderer` runs fixtures, stories, and Studio comparison replays through `ree`; intentional script-visible changes must be backed by Studio comparisons before updating goldens.

## Layers and extensions

The core engine has no UI layout, text shaping, or input renderer; hosts attach one via `Engine::with_layers(options, layers)`.

During `lua::start` (`Engine.Start`), `ree` installs core behaviors, derived views, 3D world hooks, and static GUI defaults (`services::install_gui_behaviors`), runs each `Layer::install` in order, and then constructs the `DataModel`—keeping instance serials, member dispatch, and frame-phase ordering consistent with or without layers.

- **Registration hooks:** Layers register behaviors (`engine.behaviors`: `add_method`, `add_getter`, `add_setter` via `services::method`/`getter`; lookup walks superclasses and last registration wins), property/hierarchy/instance-freed callbacks (`engine.hooks`), and scheduler phase hooks (`state.sched.add_hook(Phase::Render, ...)`).
- **Per-engine state:** Store host state in an `Extension` (`engine.extension_or_insert_with(T::default)`). `Engine::teardown` invokes every extension's `teardown` so closures and Lua references release cleanly.
- **Core fallbacks without a GUI layer:** `GetMouseLocation` returns `(-1000, -1000)`, `GuiState` stays `Idle`, `TextService:GetTextSize` uses compiled-in Studio advance tables (`src/text_measure.rs`), `UserInputService.MouseDeltaSensitivity` and mouse/gamepad sensitivities default to `1`, and unimplemented GUI members report `missing`.
- **`TextService` without a GUI layer** (`src/text_measure.rs`, measured on a 0.747 client and server: `tools/parity/probes/text_bounds.luau`):
  - `GetTextBoundsAsync(params)` is the measurement `GetTextSize` makes, for the params' `Font` face: an `Enum.Font` face measures as `GetTextSize` does for it, except `SourceSansItalic`, which `GetTextSize` measures upright. `Width` is the frame's width, with no wrapping when it is not above 0. `GetTextBoundsParams.Size` stores a whole number from 1 to 100.
  - A face no `Enum.Font` names measures as the face `data/text-faces.json` gives it: a family without the weight or style asked picks one it has. A face of its own the tables lack, a family they don't know, and rich text markup (the core has no rich-text parser) are measured as the nearest face, `SourceSans` and plain text, and report `missing`.
  - The first call of a face the client hasn't loaded yields until the next resumption point. A call that cannot yield, such as one from a metamethod, raises `thread is not yieldable`. The faces a client starts with (SourceSans's five, Arial's and Arimo's two) never yield.
  - Errors are the client's: `Argument 1 missing or nil`, `Argument 1 is invalid: expected 'GetTextBoundsParams' instance type`, `Unable to cast value to Object`, and an empty font family.
  - A server has no typesetting: `GetTextBoundsAsync` raises `Typesetting is not enabled in this DataModel` and `GetTextSize` returns `(0, 0)`.
  - A host's GUI layer (roblox-ui-renderer's) replaces both methods with its own font metrics, so the two always agree.
- **Host bridges into core features:**
  - Input actions: hosts forward device key/mouse transitions via `services::input_actions::deliver`.
  - `Path2D`: hosts supply parent rects via `path2d::set_frame_source` and signal layout via `path2d::laid_out` (without a layout host, `GuiObject` parents measure `0x0` at `(0, 0)` and `ScreenGui`/`SurfaceGui` measure `800x600`).

## Project mount (`src/mount.rs`, `src/project.rs`)

`mount_project(lua, engine, &spec, started)` runs `Engine.Start` (while scanning roots in parallel via `project::Prescan`), then mounts in strict order:
1. Studio snapshots (`<Service>.rbxm`, `.rbxmx` or `.rbx`)
2. Rojo roots, or a Rojo project file's tree (`--rojo`)
3. Data roots (`data-roots.json`)
4. Explicit mounts (`--mount`)
5. Package stand-ins (`lua/packages`: UI Labs data shapes)
6. Local player join (`begin_project` pauses here; `Mounting::finish` runs steps 7–8 so hosts like `rur` can inject story setup)
7. Studio hierarchy placeholders (`studio-places.json` / `studio-snapshots/<Place>.json`)
8. Manifest bundles

### Mounting rules

- **Rojo roots:** `<root>/<Service>/...` supports `init.luau`, `*.server.luau`, `*.client.luau`, `init.meta.json`, `.json` modules, and `*.model.json`. A directory containing `default.project.json` (e.g., Wally packages) mounts as that nested project ahead of any init script (using the project's `name`, unless the directory itself was explicitly mounted via `--mount`/`Context.Mount`/`$path`).
  - **Path sandboxing:** Nested `$path` values must remain strictly inside the project file's directory—absolute paths, UNC paths, drive prefixes, and `..` segments are rejected with a warning. Missing/refused root `$path`s or unreadable project files fall back to mounting the raw directory; missing child nodes are skipped (silently for `{ "optional": ... }`). Nesting past depth 32 or 10,000 projects per mount stops with an empty `Folder` and a warning.
  - **Symlinks & junctions:** Followed unless cyclic (a link pointing to an ancestor directory is skipped with a warning).
  - **Names starting with a dot:** Mount like any other name, as `rojo build` 7.6/7.7 builds them, so a package manager's dot folder (pesde's `Packages/.pesde`) is there for the modules that require through it: `.hidden/` is a Folder, `.x.luau` a ModuleScript `.x`, `.x.server.luau` a Script `.x`, `.x.json` a JSON module `.x`. A file named only by a suffix takes Rojo's name for it (`.luau` is a ModuleScript `.luau`, `.server.luau` a Script `""`), and files no rule takes (`.gitignore`, `.DS_Store`, `.env`, a submodule's `.git` file) make nothing. A `.git` directory inside a mounted directory mounts as an empty Folder, with a warning, and nothing in it is listed. Rojo builds a Folder for every directory in it, which can be thousands. A `.git` that is itself the target of `--mount` or a project's `$path` is listed.
- **Rojo project files (`--rojo <file.project.json>`, `src/rojo.rs`):** The project's tree becomes mounts in file order (`rojo::Tree`, read by `launch::prepare`), applied where the roots mount. A `"$className": "DataModel"` tree mounts each node's `$path` (relative to the project file; `..` allowed, since the user named the file) at its instance path; a node whose `$path` names another `*.project.json` is that project's tree as Rojo builds it (`snapshot_project_node` in Rojo's `src/snapshot_middleware/project.rs`): the tree's class, `$path`s (relative to that file) and children, then the node's own children, the node's `$className` winning only over a Folder (both with another class refused, as Rojo refuses them). That holds at the root too, so a tree that is a `$path` to a DataModel project with more services beside it is a DataModel tree; chains are followed and a cycle of project files is refused, naming it; `$className` nodes without a `$path` below a service become instances of that class (a Folder for an unknown class or a service); `{ "optional": ... }` paths that are missing are skipped quietly, other missing `$path`s are skipped with a warning (`<file> maps A.B to <path>, which doesn't exist; not mounted`, with `wally install` advice for a Wally folder beside a `wally.toml`). Any other tree (a model or plugin project) mounts at `ReplicatedStorage/<project name>` or `--rojo-at Service/Name`. `$properties`, `$attributes`, `$ignoreUnknownInstances` and `globIgnorePaths` are ignored, as roblox-ui-renderer's reader (the same module) ignores them. Files and folders mount exactly as below a root (scripts, `init` files, `.model.json`, `.rbxm`/`.rbxmx`, JSON modules, a folder's own `default.project.json`, StarterPlayerScripts' class). `--rojo` replaces `--roots` (both together are refused); explicit `--mount`s follow it. The project file's folder is the run's `Options::project` unless `--project` names one, and stands for the place's root wherever a root's folder is looked up (`mount::place_roots`: `rur.json` settings, `studio-places.json` place id and hierarchy snapshot with its lazy Studio-only placeholders, data roots, the Studio name map on a server run, manifest bundles, package stand-ins), as a root folder holding the place's `default.project.json` does. The project files and every `$path` checked are noted for prepared runs (`files::note`).
- **Module bytecode reuse:** Multi-engine hosts (`ree serve`) cache module source and bytecode keyed by file size and mtime checked directly on disk at read time (never trusting a stale mount scan). Across separate processes, compiled Luau bytecode (for both standard `require` and mutable-sandbox `debug.loadmodule`) and compact binary JSON payloads are stored in content-addressed, versioned, read-only memory-mapped `.mpack` files under `<state dir>/module-store/` (keyed by compiler ABI digest, artifact kind, SHA-256 of source bytes, and length; disable with `REE_MODULE_CACHE=0`). Each record carries a checksum of its payload (format 2), and a payload that reads back otherwise is a miss, compiled again: on Windows under heavy write load a just-written pack's pages can read zero-filled through a mapping, and Luau loads zero-led bytes as an error whose text is only the chunk name. Packs are flushed to disk before they are renamed into place; one process compacts at a time (a try-lock on `packs/compact.lock`, the others skip), only past 16 packs, not counting packs a larger one holds entirely (a compaction's inputs another process still had mapped), which are dropped and removed. Bytecode that still fails to load (kept by the process, or handed over by the store) is not the script's error: the source is compiled again. A script's source is always compiled as text, never taken for bytecode by its first byte. Under `--native`, `debug.loadmodule` reuses one loaded wrapper/chunk template per module and clones it into a fresh environment (`lua_clonefunction` + `lua_setfenv`), decoding binary JSON directly through the Luau C API.
- **Project settings (`rur.json`):** Keyed by root folder name (first matching root wins): `placeIds`, `modelAssets` (`mount`, `prefixes`), `clientGui`, `streamingTargetRadius`.
- **Engine Luau tiered JIT (`src/lua/globals.rs`, `patches/luau/24-tiered-jit.patch`):** Engine setup chunks (`vector3.luau`, `prelude.luau`, `services.luau`, `server.luau`) load without eager codegen so startup skips compiling cold setup/stub code, while arming on-demand single-proto tiered compilation (threshold 16) before they load. After startup, `--native` keeps tiered loading armed for script chunks whereas default runs disarm load-time tiering (`luau_codegen_set_tiered_load(0)`) so `interpret_modules` user scripts stay interpreted for the work clock while hot engine helpers still compile natively in place; `interpret_all_from_start` leaves all code interpreted.
- **Studio hierarchy snapshots & place content:** `studio-places.json` maps `<root>/default.project.json` to a `<Place>` name and `studioPlaceId`; `studio-snapshots/<Place>.json` compiles into a versioned, checksummed, read-only memory-mapped binary CSR index (`v2-<hash>.studio` under the shared per-user `<cache>/ree/shared/studio/` store, or `<state dir>/studio/` when `RUR_STATE_DIR`/`RUR_CACHE_DIR` is set, with read-only lookup of the shared store) supplying name+class placeholders materialized lazily on lookup/listing so `FindFirstChild` and `WaitForChild` match Studio. Plain directories with no class override inherit their snapshot class (when not Folder/script/service). Model files (`.rbxm`, `.rbxmx`, `.rbx`) under `<repo>/data/place-content/<Place>/<parent>/` replace matching placeholders with real serialized instances.
- **Data roots & Studio names:** `data-roots.json` mounts matching `<project>/external/<Name>/src` directories as roots. `studio-name-map.json` restores illegal-on-disk Studio names (colons, slashes, trailing dots) on server mounts (client mounts keep filesystem names).
- **Local content files:** Relative local paths (`output/x.mesh`, `file://<path>`) resolve against `Options::project` (`--project`, else the `--rojo` file's folder, else first root's parent, else CWD) for pre-upload testing; recordings emit canonical absolute `file://` URIs.
- **`ModelPlan` & lazy instantiation (`project/plan.rs`):** Models, snapshots, and bundles compile once into `Send + Sync` flat arrays (`ModelPlan`). `instantiate_lazy` creates root instances up front and materializes children/properties on first script access—automatically materializing the full import region before destructive/subtree operations (`plan::before_method`) while keeping serials (`GetDebugId`), child order, refs, and `GetTagged` identical to eager instantiation. What an import makes inside a world (a `WorldRoot` or `JointsService`) is made with everything below it, since the world's assembly walks, queries and recorder read it whole, and the rigid joints an import makes after the joint index first scanned the place are indexed as they are made, so a lazily imported model's welds hold its parts together as an eagerly made one's do.
- **Model files and Roblox archives (`project::decode_model`):** Every model file (snapshots, mounts, place content, bundles, animation files, `ree lune`'s deserializers) is read by its bytes: `<roblox!` through `rbx_binary`, `<roblox` through `rbx_xml`, and a Roblox archive (`.rbx`, a ZIP) through `ror-archive`, which checks it and writes the values its writer kept outside the scene (script sources, shared strings) back into a standalone `.rbxl` / `.rbxm` first. `rbx_binary` reads the stored scene alone with those properties dropped and no error, so nothing reads it unflattened. An archive the reader refuses is an error naming the file (a mounted file that does not decode warns `<file>: <reason>; not mounted`), and the reader's notes (content kept as opaque objects, which reads as empty; what it read past) are Output warnings that name the file; a file with notes is not kept between runs or in a bundle's `.plan`, so each run reports them. A `.rbx` mounts by `--mount` and the other options that name a file; Rojo trees mount only the files Rojo reads, so none there (`rojo::Tree` drops a `$path` to one).
- **Rojo JSON models (`*.model.json`, `project/json_model.rs`):** Matches Rojo 7 (explicit or implicit typed properties resolved via `rbx-dom` and `ree`'s newer reflection database, round-tripped through `rbx_binary`). Invalid files warn and skip. XML and binary models both resolve enums via `ree`'s reflection and preserve unknown properties.

## Asset bundles (`src/project/model_assets.rs`, feature `bundles`)

Projects can declare lazy-loaded model bundles in `<project>/asset-manifest.luau`:

```lua
return {
	["Models/Props"] = { AssetId = 1234567890, Version = 3 },
	["Models/Props/_Loose"] = { AssetId = 2345678901, Version = 1 },
	["Models/Props/Tall Lamp"] = { AliasOf = "Models/Props/Lamp" },
}
```

`rur.json` `modelAssets` (or `--assets-at <Service.Path> --assets <prefix>,...`, `*` for all) mounts only folders and placeholders at startup. Accessing a placeholder imports the bundle in place (replacing the placeholder with the bundle's single root instance while keeping its path leaf name; `_Loose` bundles unpack children directly into the parent folder; multi-root bundles warn and wrap in a folder). `AliasOf` chains lazily clone the target `Model` on explicit name lookup (`FindFirstChild`, `WaitForChild`, indexing—not listings), warning if the target isn't a `Model` or doesn't exist. Where a script could otherwise tell a bundle was not in place, it is imported first: a placeholder passed to an engine method (`AddTag`, `TweenService:Create`, ...), the bundles waiting at an instance something is parented to (so they come first in its children), the bundles in a subtree that enters a world (the world's walks, queries and recorder read it whole), and the bundles whose instances carry a tag `CollectionService:GetTagged` asks for (`GetAllTags`: any tag). A destroyed placeholder a script still holds is its bundle's root (class, values, attributes, tags; no children). Connecting `GetInstanceAddedSignal`/`GetInstanceRemovedSignal` of a tag imports the waiting bundles carrying it as their subtree enters or leaves the DataModel, whichever way it leaves (`Parent = nil`, `Remove`, `Destroy`, `ClearAllChildren`; on a loopback client, its server's too). A bundle's tags are read from its plan once and kept in `<state>/model-bundles/tags.json`, by the source's shape and the asset version its manifest line pins, for good, whichever project run from that state dir named it (else by its file); a lookup fetches and reads the bundles it cannot place at once, warns about one it cannot read, and reads nothing of a bundle that was destroyed. The Studio-only stand-ins a bundle replaces go with no event.

### External asset worker protocol (`REE_ASSET_WORKER`)

Hosts can inject a custom `BundleSource` via `engine.set_bundle_source`. By default, `AssetWorker` spawns `REE_ASSET_WORKER` (passing any whitespace-separated arguments in `REE_ASSET_WORKER_ARGS`, followed by `--offline` when offline) and exchanges newline-delimited JSON:

- **`REE_ASSET_WORKER_ARGS` quoting:** `'...'` single quotes are verbatim (recommended for Windows paths ending in `\`, e.g. `'C:\my dir\'`). `"..."` double quotes follow Windows command-line backslash rules: backslashes are literal unless immediately preceding `"`, where `\"` yields a literal `"` and `\\"` yields a literal `\` and closes the quote (so UNC paths like `"\\nas\My Tools\w.mjs"` stay intact). In standalone mode, workers start with `<state dir>` as their working directory, so any relative paths inside `REE_ASSET_WORKER_ARGS` resolve from `<state dir>`—pass absolute paths instead.

| Request (stdin) | Reply (stdout) |
|---|---|
| `{"command": "catalog", "project": "<dir>", "manifest": "<file>"}` | `{"bundles": ["Models/Props", ...]}` |
| `{"command": "asset", "uri": "rbxassetid://<id>?version=<v>", "out": "<file>"}` | `{"file": "<path>"}` |

Replies containing `"error": "<text>"` report failure. `ree` never handles worker credentials. The `uri` of an `asset` request is built from the asset id and version a content id was read as (`content_id::AssetRef::worker_uri`); no text a script wrote reaches the worker.

### Standalone path and environment normalization

In standalone release builds (even when `--repo` is passed), clients resolve paths before launching services or moving worker CWD into `<state dir>`:
- Relative `PATH` entries resolve to absolute paths (on Unix, empty entries become the client's CWD; on Windows, empty entries stay empty). `NODE_PATH` ignores empty entries on all platforms.
- **Worker binary resolution:** On Windows, bare `REE_ASSET_WORKER` names resolve once in the client (beside client exe → system/Windows dirs → `PATH`, adding `.exe` if extensionless) so copied services never accidentally run a different binary beside their copy. On Unix, bare names stay bare for OS `PATH` lookup. Paths containing directories resolve against the client's CWD.
- **Normalized service key:** Standalone services receive the full client environment and hash it after resolving known paths (`PATH`, `NODE_PATH`, user/temp dirs, state overrides, `RUR_ENGINE_DUMP`, `RUR_CLOCK`, profile outputs, `REE_ASSET_WORKER`), uppercasing Windows var names, and pinning `RUR_STATE_DIR`. Values are never stored in service records. Unknown relative env vars resolve against `<state dir>` consistently for both direct runs and services.
- **Relative per-user dirs:** Relative values of `LOCALAPPDATA`, `HOME`, `XDG_CACHE_HOME`, `APPDATA`, and `USERPROFILE` are ignored when choosing the default cache path, then absolutized (along with `TMP`, `TEMP`, `TMPDIR`) before reaching workers.
- **Worker output handling:** Standalone workers receive absolute project, manifest, and output paths; relative reply `file` paths resolve in `<state dir>`. If a worker writes a bundle to a different path than requested, `ree` copies it into `<state dir>` so the compiled `.plan` stays cached in state. (Animation replies pointing to the same file via symlink/alias skip copying by file identity.)
- **Caching:** Bundles cache at `<state dir>/model-bundles/asset-<AssetId>-v<Version>.rbxm` with memory-mapped compiled `<file>.plan` files beside them (keyed by `build.rs` conversion digest and file stamp). `recent-*.txt` triggers background pre-decoding on subsequent runs of the same scene.

Checkout builds and embedded library hosts preserve their original relative paths, worker lookup, and service key rules.

## Core engine API and data model (`src/`)

Each mounted project owns one single-threaded (`!Send`) `Rc<Engine>` paired with one `mlua::Lua` (always drop `Lua` before calling `engine.teardown()`; `Emulator` enforces this). Built-in Luau chunks (prelude, services, `vector3.luau`) compile to bytecode once per process (`lua::modules::load_engine_luau`). In loopback mode, the client `Engine` holds a link to its server (`Engine::peer`, `loopback::link`, `loopback::join`) so stepping the client steps both engines together. A host that makes its own client (rur's stories) starts the server with `loopback::start_server`, readies its client with `loopback::ready_client`, links them, and starts the server's harness and the join with `record::run::begin_server`.

- **Fast DOM access:** Read instances via `state.dom.at(id)` and properties by pre-interned `NameId` (`K::Size as NameId`, or `reflection.name_id("X")` cached once at setup), converting with `Value::as_*()`. An instance's `children` (`dom::Children`, in the order a client keeps them in: below) is read through `iter()`, `len()`, `first()`, `last()`, `to_vec()`, `slice()` or `copy_to()`; a host that puts a parent's children in another order hands the whole order to `Dom::reorder_children`. Call `lua::instance::reached` / `find_child_where` before handing instances to Luau so lazy bundle placeholders materialize first.
- **Child order (`dom::Children`; Studio 0.747, a playing client and a server alike, in every container: `tools/parity/probes/child_order.luau`):** A parent keeps its children in the order a client keeps them in: a child is appended, a last child dropped, a list of 20 or fewer closes the gap a child leaves, and out of a list of 21 or more the last child takes the taken one's place. So after a child goes from the middle of a long list its last child lists in that place in `GetChildren` and `GetDescendants`, the finds among children of one name (`FindFirstChild`, `FindFirstChildOfClass`, `FindFirstChildWhichIsA`, `WaitForChild`, indexing by name) take it first, `Destroy` destroys a list first to last and `ClearAllChildren` last to first in that order, and a `Clone` copies it; a child put back goes last. Each child knows its place (`Dom::sibling_place`), so taking one out costs the same host time wherever it is and however many siblings it has.
- **Deep trees:** a script can nest instances deeper than any thread's stack holds frames for, so engine code that walks the tree for a script never recurses: `Dom::descendants`, `subtree_post_order`, Clone, Destroy, the recursive finds, QueryDescendants, an attachment's or bone's frame up its chain and a CurveAnimation's Folders each keep a stack of their own, in the order a recursion would visit. ### Coercion, transforms, and Luau library parity

- **Property coercion (`convert::coerce`, measured in client):** Numbers coerce numeric strings and treat non-numbers as `0`; `int` truncates (clamping overflow/non-finite to min); `int64` rounds half away from zero (`0` on overflow); booleans use Lua truthiness; strings accept strings and numbers. `Vector3` and `CFrame` preserve exact `f32` values. Part `CFrame` and `BulkMoveTo` keep rotations when `|RᵀR - I| <= 1e-5` per entry, a joint's `C0`/`C1` when it is within 5e-7 (Studio 0.747, `joint_c0_tolerance.luau`), otherwise orthonormalize (`CFrame:Orthonormalize()`, identity for zero column); `Model.WorldPivot` preserves arbitrary rotations.
- **Replicated model precision (`project::received`, verified on 2,347 bundle rotations):** Server load orthonormalizes joint `C0`/`C1`, attachments, and bones (keeping pivots intact), then non-axis-aligned rotations quantize through Roblox's 15-bit smallest-three quaternion wire format (`* sqrt(2)` in `1/16383` steps, orthonormal within ~`1e-4`). Positions, axis-aligned rotations, and `:Clone()` preserve exact floats.
- **Chunk names:** Scripts compile with their full instance path (`ReplicatedStorage.Module:3:`, matching client; `chunknames.luau`). Unlike Roblox, identical sources in distinct modules keep their own names.
- **Luau 0.748 builtins and compiler:** `math.isnan`, `math.isinf`, and `math.isfinite` are fast-call constant-folded builtins accepting numbers or numeric strings (`math_classify.luau`). `buffer.readvectorf32x*`/`writevectorf32x*` stay hidden behind `DebugLuauBufferVector*` flags (off in live 0.747 and 0.748; `buffer_vector_f32.luau`). The removed Luau integer type is absent. A numeric `for` loop's first index is its start as written, `-0` included, also where the compiler unrolls the loop (`loop_start.luau`, a 0.748 client and server; the client's `LuauCompileLoopUnrollNegativeZero`).
- **`CFrame:FuzzyEq(other, eps = 1e-5)` (`cframe_fuzzyeq.luau`, Studio 0.744):** Single precision using `|eps|` (raises if `|eps| > 0.1`; `NaN` returns `false`; accepts numeric strings; exact client arg errors). Position matches per axis if `a == b` or `|a - b| <= |eps| * (|a| + 1)`. Rotation matches if `sqrt(sum((RaᵀRb - I)²)) / sqrt(2) <= |eps|` without FMA.
- **`CFrame.fromRotationBetweenVectors(a, b)` (`cframe_rotation_between.luau`, a 0.747 playing client, 478 pairs bit-exact):** Single precision from the vectors as given (not made unit): the quaternion `(a × b, w)` with `w = sqrt(|a|² · |b|²) + a · b`; when `w < 1e-5 · sqrt(|a|² · |b|²)` (within about 0.26° of opposite) a half turn `(axis, 0)` instead, the axis `(0, -a.z, a.y)` if `|a.x| <= |a.y|`, else `(-a.z, 0, a.x)`. Then `q * (1 / sqrt(q · q))` and the quaternion-to-matrix step, which normalizes again (X to Y reads `R00 = -1.1920929e-07`, `R01 = -1.0000001`). A zero vector gives NaN. Subnormal intermediates flush to zero, as every script's float32 arithmetic does (the float mode below); argument errors keep the other constructors' unpositioned form (`known.json`).
- **`CFrame:AngleBetween(other)` (`cframe_angle_between.luau`, a 0.747 playing client, 213 pairs bit-exact):** In doubles from the stored floats: `x = (trace(AᵀB) - 1) / 2`, the trace summed column by column (`dc = (A0c·B0c + A1c·B1c) + A2c·B2c`, then `(d0 + d1) + d2`), clamped to `[-1, 1]` (a rotation against itself can read a trace past 3, giving 0), then `atan2(sqrt(1 - x²), x)` (`acos` differs in the last bits on a quarter of the pairs). Positions are ignored; matrices that aren't rotations go through the same steps. Errors are the client's: any count but 2 raises `Invalid number of arguments. CFrame:AngleBetween expected 2, got <n>.` (no position); a non-CFrame raises at the calling line, argument #2 in the `:` call's form also for a `.` call (`known.json`).
- **Datatype argument errors (`datatype_errors.luau`, a 0.747 playing client and server, 619 lines):** A wrong operand, argument or self raises the client's one-line string, never a conversion error naming Rust types or carrying a traceback. Two families, per member as measured: Luau-style checks raise from the calling line (`invalid argument #2 (Vector2 expected, got number)`, `missing argument #1 to 'Abs' (Vector2 expected)`; self is named as a `.` call names it, later arguments take the `:` call's form, since a method found through `__index` cannot tell the two apart), reflected ones raise without a position (`Argument 3 missing or nil`, `Unable to cast double to Vector2`, `CoordinateFrame` for a CFrame, `Array`, `bool`), each in the member's own order (Lerp: self, alpha, goal; Cross and ExpandToGrid: the last first; CFrame.Angles: 3, 2, 1). A reflected float takes a number, a numeric string (hex and spaces too) or a boolean. Operators check whichever side runs them (`1 + CFrame` is `invalid argument #1 (CFrame expected, got number)`); Vector2's `*`, `/` and `//` raise `attempt to multiply a Vector2 with an incompatible value type or nil` and accept numeric strings. - **Datatype operators (`datatype_errors.luau`, a 0.747 playing client and server):** Rect has no arithmetic and DateTime no `<` or `<=` (the VM's `attempt to perform arithmetic (unm) on Rect`, `attempt to compare DateTime < DateTime`). Vector3int16 and Vector2int16 `*` and `/` take a number on either side or another vector of the type; any other operand reads as 0 without an error (`Vector3int16.new(1, 2, 3) * "x"` is 0, 0, 0). - **`CFrame.new(x, y, z, qx, qy, qz, qw)` (`cframe_new_quat.luau`, a 0.747 playing client, 134 quaternions bit-exact):** The quaternion is made unit first, `q * (1 / sqrt(q · q))` with `q · q = (x² + y²) + (z² + w²)` in single precision, then turned into the matrix (the same step `Lerp` and `fromRotationBetweenVectors` end with). A non-unit quaternion gives a rotation (`(1, 2, 3, 4)` reads `R00 = 0.13333333`), a unit one can read a float step off (90° about Z reads `R01 = -1.0000001`), `q` and `-q` give the same matrix, a zero quaternion gives NaN, and one whose squared length overflows scales to zero (the identity). Subnormal intermediates flush to zero (the float mode below): quaternions near `1e-20` read NaN and infinities.

### Float mode (`src/lua/float_mode.rs`, `patches/luau/19-float-mode.patch`)

Measured in Studio 0.747 on a playing client, a server and a plugin in the edit DataModel (`float_flush.luau`, captured twice per side, identical): the engine runs scripts with x86's SSE flush-to-zero on and denormals-are-zero off, so an operation whose result is subnormal (below `2^-1022` for a double, `2^-126` for a float32) gives `0`, while a subnormal operand is still read as itself.

- **Flushed:** double arithmetic with a subnormal result (`sub * 3`, `sub + sub`, `minNormal / 2`, `2 ^ -1074`); float32 conversions and arithmetic (`buffer.writef32`, `string.pack("f")`, `vector.create`, `Vector3.new`, `CFrame.new`, `Color3.new`, a float property's write, a product of tiny vectors, `Magnitude`, `Unit`); `string.format("%.17g", sub)` (the C library's formatting runs in the mode); constants the compiler folds (`2 ^ -1074` and `2.2250738585072014e-308 / 2` compile to `0`, as do a local table's constant fields, which fold like literals).
- **Kept:** reads (`buffer.readf32`, `string.unpack("f")` of a subnormal bit pattern); comparisons (`sub > 0` is `true`); scaling up (`sub * 2^60`), `math.sqrt`, `math.abs`, `math.min`/`max`, negation; `tostring`, `tonumber`, number literals, `math.ldexp(1, -1074)`, `HttpService:JSONDecode("[5e-324]")` and `JSONEncode`; a double property (`NumberValue.Value`).
- **Where:** a server everywhere. A client and edit mode everywhere but the render step, which keeps subnormals: `RenderStepped`, `PreRender`, `BindToRenderStep` callbacks at any priority, threads those signals resume, what they spawn and defer, and `TweenService`'s client step (a tweened property's `Changed` handlers). `Heartbeat`, `Stepped`, the simulation events, resumptions after a wait and deferred work queued outside the render step flush. Every context folds constants in the flushing mode, so one compile (and the shared bytecode caches) serves all.
- **How:** each VM gets the mode at Engine.Start (`lua_setfloatmode`), and the scheduler switches a client's VM to keeping subnormals for its render step. The VM applies the mode at its outermost entry from the host (a call or a resume; a nested entry only counts itself, since reading the mode register waits for the float operations in flight) and restores the caller's when that returns or an error is caught; the compiler folds in it when its options ask (`float_mode::COMPILE_FLUSH`). No Rust code changes the float environment (Rust assumes the default one, which is why `_mm_setcsr` is deprecated): a host's own math outside Luau keeps subnormals, while the Rust a script calls (datatype math, property conversions) runs in the mode, as a real engine's code runs in its scripts' mode. Engine work outside a script's call (the scheduler, a tween's interpolation) keeps IEEE results.
- **Cost:** none measurable on whole runs (interleaved A/B, minimum of 15: 4,000 resumes and handlers a frame 0.99x, Luau `pcall` 0.99x, a `table.sort` comparator 1.015x, about 0.5 ns per call from C, arithmetic 1.00x).
- **Native code** follows Luau's code generator, which drops a multiplication by `1` (and turns a division by a power of two into a multiplication), so natively compiled `sub * 1` keeps `sub`, as Roblox's native code does.
- **Platforms:** x86-64 only. AArch64's `FPCR.FZ` also reads subnormal operands as zero (it would break the kept list) unless FEAT_AFP's `FIZ`/`AH` controls are set, which also change NaN and min/max results, so an ARM build (macOS releases) and WebAssembly keep subnormals everywhere, as before (untested on ARM). The C library's own routines run in the mode as the engine's do: `%.17g` and `ldexp` match a client with Windows' C runtime; another C runtime can format or scale a subnormal differently.

## Engine functions (`src/lua/cfunction.rs`, `src/lua/builtins.rs`, `patches/luau/20-engine-functions.patch`)

On a playing client and a server every engine function is one C function (measured, Studio 0.747: `tools/parity/probes/engine_functions.luau` and `engine_functions_require.luau`): `debug.info(f, "sln")` gives `[C]`, `-1` and its name (`print`, `wait` for `task.wait`, `new` for `Vector3.new`, `GetService` for `game.GetService` read as a value, `Spawn` for the `Spawn` alias, `newPhysicalPropertiesWithClampedMsgClosure` for `PhysicalProperties.new`), `debug.info(f, "a")` gives `0, true`, and an error raised inside one has no frame of its own: an `xpcall` handler's traceback lists the handler, the script line that called the function and the frames below it, and the Output's stack of an uncaught one starts at that line. An argument error is positioned at the calling line, and has no position when a C function such as `pcall` calls it directly (`luaL_where(L, 1)`). A callback an engine function calls finds it one frame up (`debug.info(3)` in a `__tostring` that `print` calls is `[C] print`), and a thread waiting in one shows only the line that called it.

ree makes each engine function a C closure of that name over its work, so scripts see the same:

- **Over Rust** (an mlua callback answering the call protocol of `src/lua/mod.rs`: `wrapped`, `library_function`, `named`): its values are returned, its error is raised from the C function (level 1 at the calling line), and its yield is `lua_yield` from it, the values the thread is resumed with being the call's results (`task.wait`, `wait`, a signal's `Wait`, `WaitForChild`, `task.synchronize`).
- **Over the engine's own Luau** (the datatype libraries and constructors the prelude serves, `utf8.graphemes`, the service methods written in Luau, read as values or called with `:`): run in protected mode and yieldably (`lua_pcallyieldable`), its error raised again from the C function as it was raised. That Luau counts error levels past the C function's frame (`services.luau` `ScriptLevel`).
- **A body in the C frame** (`src/lua/builtins.rs`): `print` and `warn` (each argument's `__tostring` called from it, unprotected, so its error reaches a handler at the raise), `require` (a module's chunk run from it, yieldably, through a continuation, so a module that waits keeps its requirer waiting) and `coroutine.create` / `wrap` (their argument checked there).

The methods of the datatypes with methods (CFrame, Color3, UDim2, Vector2, Ray, Region3) are named the same way; their `:` calls go as before. A datatype error positioned at its caller looks through the engine function's frame (`lune-roblox`'s `set_engine_frame`).

On the work clock a script's call of an engine function is one call, the Rust or Luau it runs for the call part of it (`lua_setenginecfunction`). A global's or a library's function costs what a client's C function does: a C call (`LUAU_CCALL`, 5.77 ns) and, its first in a frame, a C function's first call (`LUAU_COLD_CFUNC`, 2.5 us, as measured for the libraries and the task functions): `print`, `warn`, `require`, `wait`, `spawn`, `delay`, `settings`, `loadstring`, `collectgarbage`, `os.time`, `os.date`, the `task`, `coroutine.create` / `wrap`, `debug` and `utf8` functions, `Instance.fromExisting` and the `SharedTable` library, where the engine Luau they were cost a host call (`LUAU_HOSTCALL`, 15 ns) and its first call (`LUAU_COLD_HOSTFUNC`, 0.9 us): 9.2 ns less a call and 1.6 us more once a frame each. What the engine serves (a datatype's constructors, functions and metamethods, an object's methods read as values or written in Luau, a SharedTable's reads and writes) costs what the engine Luau that stood for it did, that host call and first call, which are the measured prices of a datatype's operation; an engine function that is a metamethod is priced so too. The functions that were C functions already (`tick`, `time`, `os.clock`, `DateTime.now`, the enum methods, `Disconnect`, the datatypes' methods) and a `:` call of a method written in Luau cost what they did.

An engine call that raises (an engine function's, an Instance member's read, write or method) costs what a client spends on the error, past its call (Studio 0.747, a playing client and a server alike; cost.rs `RAISED`, `RAISED_AT_CALLER`, charged where the engine raises it, `lua/cfunction.rs` `charge_raised`): 3.4 µs for a plain error, in the engine's words (`Argument 1 missing or nil`, an unknown member, a service name, a spatial query's; a client's 3.1 to 3.7), and 2.5 µs for one positioned at the calling line, an argument check in Luau's words (`invalid argument #1 to 'delay' (number expected, got string)`; a client's 2.0 to 3.0). An error raised into the engine's own Luau, which handles it or raises it again from its engine function, is charged once, when it reaches the script. Not matched: a refused property write costs a client more (4.5 to 4.8 µs; 7.4 to 7.7 for a value of the wrong type for a datatype or string property), and a script's own errors (1.8 to 2.4 µs) and those of a datatype's methods and operators and of the proxy values cost nothing here.

Not matched: `require` runs a module's chunk on the requiring thread, under `[C] require`, where a client runs it on a thread of its own (`debug.info(2)` in the chunk is nil there, a traceback in it lists the module alone, and the thread that began loading a module that waits shows only its require line). The iterator `utf8.graphemes` returns, the methods and metamethods of the prelude's proxy values (`RaycastParams:AddToFilter`, `SecurityCapabilities`' methods), the Luau a require from a thread that cannot yield runs, and the engine Luau under a BindableFunction's handler (which runs on a thread of its own, as a client's does, but under the engine's `xpcall`) are still Luau frames. A method written in Luau runs for a wrong `self` passed with `.`, where a client raises `Expected ':' not '.'`.

Copies keep their prices on the work clock; `JSONEncode`, priced by the values it writes, raises the script timeout's error once its own price passes the run's script timeout.

## Scheduler, timing, and guards (`src/scheduler.rs`, `src/watchdog.rs`)

### Frame phase order

**Play mode (`--mode play`, measured in client):**
1. The frame's start: in a loopback run what the other side sent (`RemoteFunction` callbacks and answers), then legacy `wait` / `delay` / `spawn` resumptions → full deferred flush (remote events and replicated changes among it). All of it reads the last frame's `time()`, equal to `Workspace.DistributedGameTime`, on a client and a server alike (`resumption_time`, loopback `remote_time`, Studio 0.747); the frame's own clock (`os.clock`, the timers' deadlines) has already moved on
2. `PreAnimation` (`time()` moves to the frame's time here) → `Animator` step (when enabled)
3. `Stepped` / `PreSimulation` → `Motor6D.Transform` apply → free-flight step → `Workspace.DistributedGameTime` takes the frame's time
4. `PostSimulation`
5. Due `task.wait` / `task.delay` threads (in scheduled order, using one clock snapshot at phase start) → single deferred pass (newly deferred work waits)
6. `Heartbeat` → `LogService.MessageOut` flush
7. Render step: `BindToRenderStep` callbacks → `RenderStepped` / `PreRender` → `TweenService` step → full deferred flush (tween events first, then callback-deferred work)

Edit mode (`--mode edit`) keeps Studio's edit order (flush after each resumption, tween step right after callbacks; display cadence keeps 240 Hz edit Heartbeats).

### Timer, TweenService, and re-entrancy rules

- **`Workspace.DistributedGameTime` (`distributed_game_time`, loopback `distributed_game_time`, Studio 0.747, a playing client and a server alike):** The game time as of the frame's simulation step, each side its own: `time()` moves at `PreAnimation`, `DistributedGameTime` after `PreSimulation`, so `PreAnimation`, `Stepped` and `PreSimulation` read the last frame's and `PostSimulation`, the `task.wait` resumptions and `Heartbeat` the frame's, equal to `time()`; before `PreAnimation` (the legacy resumptions, a remote's handlers) both read the last frame's. A script may write it (a number property's coercion: `"x"` and `true` are 0); the value holds until the next simulation step. A server fires `Changed` for every step, a client only for a script's write. Edit mode reads 0, like `time()`.
- **`task.wait` / `task.delay` (`task_delay_time`, Studio 0.746):** Measures elapsed time on `os.clock` (frame time + in-frame script work) and wakes at the first task-queue phase at or past target time. Legacy `wait`/`delay`/`spawn`, `Debris`, and `WaitForChild` warnings use frame time only. Recorded (`RUR_CLOCK`) and frozen clocks add no work time.
- **Where a thread cannot yield (`yield_refused`, `yield_refused_require`, Studio 0.747):** Inside a metamethod, a `table.sort` comparator, a `string.gsub` callback or another call from C, a call that would yield raises before it registers anything, without a position: `thread is not yieldable` for `task.wait` (checked before its argument), `wait`, `WaitForChild` of a missing child (whatever its timeout), `require` of a module another thread is loading, a `BindableFunction:Invoke` with no handler or whose handler yields, `InvokeServer` and `InvokeClient`; `thread cannot be yielded to Wait` for a signal's `Wait`. `coroutine.yield` keeps the VM's own error. The thread's later waits take their own time and return their own results. Calls that don't need to yield still answer there: `WaitForChild` of an existing child, an `Invoke` whose handler returns without yielding (a handler that yields goes on in its own thread), `ContentProvider:PreloadAsync` with nothing to load, and threads started there. A module that must load, required there, loads in a thread of its own: `require` returns its result when it loads without yielding, else raises while it goes on loading, and a later `require` gets the result. A missing argument (`WaitForChild(nil)`, `InvokeClient(nil)`: `Argument 1 missing or nil`) and a `Wait` on a value that is no signal raise their own errors first; the side checks (`InvokeServer` on a server, `InvokeClient` on a client) come after the refusal. `task.wait`'s argument error names the line that called it.
- **`TweenService` `Color3` interpolation (`tween_color`, Studio 0.747):** Follows Roblox's live `DFFlagStyleTransitionColorSpace` (off as of 2026-11-13): blends per channel linearly as `a + (b - a) * eased` in `f32` (allowing `Back`/`Elastic` overshoot past `0..1`; `Color3:Lerp` is also linear; `ColorSequence`, `BrickColor`, and attributes are not tweenable). *(Parts store exact `f32` `Color` rather than flooring to `1/255` steps.)*
- **Deferred re-entrancy limit:** Chains of deferred events and `task.defer` stop at depth **80**, logging Roblox's exact `Maximum event re-entrancy depth exceeded...` or `Maximum re-entrancy depth (80) exceeded calling task.defer` messages.
- **Script timeout (`src/watchdog.rs`):** Non-yielding resumptions error with `Script timeout: exhausted allowed execution time` after 10 s of the work clock (default) or 60 s host time, firing on every safepoint so `pcall` cannot trap it. The work counts from the resumption's start (nested ones count with the outermost): every call in it, a long engine or library call before the watchdog arms included. The watchdog arms VM interrupts once a resumption runs 0.1 s of host time (an eighth of a shorter limit, at least 5 ms) or an engine call charges an eighth of the limit; the check then weighs the work clock at safepoints the VM's own counts fix (every 1024th script call or loop step, and the first safepoint after a call whose size work or engine charges passed a step), so a timeout falls on the same safepoint in every run, with or without `--profile`, never before the limit, and a call that takes its resumption past the limit is followed by the timeout at the next safepoint, as a client stops such a script (roblox-sim, Studio 0.747: `ScriptContext:SetTimeout` at half a 3,000,000-number sort's time). Three timeouts exit `126`; wall-clock cap (`600 + 20 * --seconds` s) exits `124`; parent-process exit triggers `125`. Any other run whose status is `error` (its harness or a frame failed) exits `1`, with its summary printed and its recording written as usual ([cli.md](cli.md#exit-codes)).
- **Held-value cap (`src/lua/refs.rs`):** Protects `mlua`'s 1,000,000-slot reference thread by raising a script error at **900,000** slots for `task.spawn`/`defer`/`delay`/`spawn`/`delay`/`Debris:AddItem`/`BindableEvent:Fire` and **950,000** for waits (`task.wait`/`wait`/`Signal:Wait`/`WaitForChild`).

## Work clock (`src/cost.rs`)

`os.clock`, `tick`, `DateTime`, `elapsedTime`, and `GetServerTimeNow` advance within each frame by deterministic, client-calibrated work charges so frame-budgeted scripts behave like they do in Roblox:

- **Luau execution (`patches/luau/02-work-counters.patch`, `15-input-size-work.patch`, `25-buffer-cache-tiers.patch`):** Charges every VM instruction by kind (`INTERPRETED_OPS`, `NATIVE_OPS` for `--!native`), object/table-storage allocations, rehashed keys, C calls, unsafe `GETIMPORT` lookups (`+7.9 ns`, `LUAU_SLOW_IMPORT`), and input-size-scaled library work (`table.find`/`insert`/`remove`/`move`/`unpack`/`pack`/`clear`, string creation/search/case/pattern steps, `utf8`, `buffer` ops, `JSONEncode`/`JSONDecode`). Large new buffers (> 1 KB fresh memory; >= 64 KB segment setup) and large buffer copies/fills/writes (> 64 KB L2/L3 tier; > 1 MB DRAM tier) are priced across CPU cache tiers. Engine-internal Luau (`prelude`, `services`, `vector3.luau`) and host C allocations (`lua_sethostcfunction`) are excluded; `SharedTable` operations are priced directly in `src/lua/shared_table.rs` from Studio 0.748 client measurements.
- **Engine & datatype operations:** Charges Instance reads (+40 ns for lowercase first-letter fallback), writes, methods, `Instance.new`, `Clone`, DataModel enter/leave, `Destroy`, list returns, child walks, ray/spatial queries, `EditableMesh`, datatype constructors/allocating ops (`datatype_price`), and scheduler resumptions (`RESUMED_WAIT` 0.35 us, `RESUMED_DELAY` 0.20 us, `RESUMED_SIGNAL_WAIT` 0.445 us, `RENDER_STEP_DISPATCH` 1.55 us; first handler on a frame event is free; disconnected deferred handlers keep queue charge only).
- **Cold & first-use modeling (`patches/luau/16-cold-attribution.patch`):**
  - First instance touch/frame: 45 ns (part) / 270 ns (GUI), +320 ns for isolated non-contiguous touches (`COLD_TOUCH_ALONE`).
  - First member use/frame: read +0.5 us, write +1.4 us, call +0.8 us.
  - First engine path/frame (`PATH_FIRST`): Clone 25 us (+class, 55 us total for Part), Destroy 10 us, Workspace enter 13.5 us (26 us w/ Part), PivotTo 16 us, part geometry write 9.5 us, BulkMoveTo 28 us, Emit 4.4 us, QueryDescendants 6.6 us, GetDescendants 3.6 us, emitter Enabled 2.4 us—plus per-instance cold fees (`clone_cold`, `destroy_live`, `PIVOT_COLD_PART`, etc.).
  - First script call/frame: C function +2.5 us, engine-served function (a datatype's operation, an object's method; "Engine functions") +0.9 us, rare prototype +0.7 us.
  - First pre-frame Luau object touch/frame (`lua_coldtracking`): table 200 ns, closure 30 ns, proto 5 ns, executed cold instruction 0.85 ns (armed per-instruction via opcode markers so unexecuted branches stay uncharged).
- **GC pricing & deterministic GC clock (`patches/luau/03-gc-clock.patch`):** Charges `8.6 ns` per script-allocated object (`LUAU_COLLECTOR_OBJECT`, booked to the allocating instruction). Luau's GC paces strictly on the deterministic work clock (`lua_setgcclock`) rather than wall time so GC steps fire at identical points across runs.
- **Place & device scaling:** Client `Text` writes with `AutoLocalize` pay ~33 us + 0.43 us/char (`REE_LOCALIZED_PLACES` customizes; `REE_MATCH_PLACES` scales workspace geometry writes by 1.55x). `--device phone` multiplies desktop prices by **2.77x** (calibration range `2.13–4.16x`).
- **Calibration accuracy (`tools/cost-parity`):** Fitted against Studio 0.744 + 0.747 rendered clients (605 workloads, 182 held out): median held-out error **16.5%** (`0.63–1.35x` p10–p90 across all 182 held-out rows including cache-tiered large buffers; `p90/p10 = 2.14x`). On 13 held-out macro game workloads (casts, card grid, server loop, scroll, step lists), total clock reads `0.53–1.06x` real client time (`cost::BENCH_BANDS`). `REE_FROZEN_CLOCK=1` freezes in-frame work advances; `Options::clock_probe` (`--timing-check`) scales in-frame work across client variance bands.
- **Moves and ancestor reads (`instance.rs` `reparent`, `cost.rs` `reparent_chains` and after; Studio 0.747, a playing client, measured by subtree size, depth and place):** A `Parent` write pays for the two ancestor chains it walks (each ancestor both chains keep, each it leaves and joins, and each it leaves or joins times the other chain's length, so a move between two chains 1,000 deep costs about 2.9 ms, as a client's does) and for every instance it carries, the written one included: inside the DataModel about 0.075 µs an instance (a GUI object 1.85, a `LayerCollector` 0.48, a `Sound` 0.63), outside it 0.047; a part whose nearest `WorldRoot` changes 0.90 µs for the Workspace's world and 0.70 for a `WorldModel`'s, each world it leaves or joins; an instance entering or leaving the Workspace's subtree 0.20 (a part) or 0.10; and each instance, inside the DataModel, 6 ns for each ancestor the move keeps past two, and 1.6 ns (6.0 for a part; outside the DataModel 1.5 and 6.4, into or out of it 7.8 and 10.8) for each level it sits below the moved one past the first, so a chain costs what a client's does (a `Destroy` of one grows with the cube of its depth, as a client's: each instance it takes out carries the rest). The chains' shared tail is found in one pass. Entering or leaving the DataModel keeps its per-class prices (`cost::moved`). A change to a part below WorldModels nested one in another pays 13 ns for each WorldModel above it and 1.6 ns for each pair of them, once for each change a client makes of the part (`cost::world_levels`, `cost::part_changes`: a CFrame, Position, Orientation or a part's `PivotTo` 5, Size 4, Anchored, Color and BrickColor 3, a CollisionGroup write 3 when it changes the part's `CollisionGroupId` and 2 when it does not (Studio 0.748, in the Workspace and below a WorldModel in ReplicatedStorage alike), another property or a `Parent` write 1, each part a Model's `PivotTo` moves 1), as a client's grows with the square of the levels (a Transparency write 9.6 µs at 100, 1.0 ms at 1,000; ree reads 0.81 to 1.22x it from 30 to 3,000 levels); a write that changes nothing and a `PivotTo` that moves nothing pay nothing more, `CollisionGroup`, `CollisionGroupId`, `Color` and `Position` written what they hold too (Studio 0.747, below 0 to 300 WorldModels in the Workspace and in ReplicatedStorage: 0.05 to 1.2 µs a write) (not modelled: a plain Model above a part costs a client about as much, a Folder 12 ns a level, and a `Position` written what it holds about 4 ns a level, 1.2 µs at 300). `IsDescendantOf`, `IsAncestorOf` and the `FindFirstAncestor` finds pay 1.2 ns for each ancestor they look at, and `GetFullName` (and an error that names an instance by it) 4.2 ns for each name and 0.14 ns for each byte. Across the probes (633 rows, 1 to 5,000 deep, 0 to 10,000 instances) ree reads 1.00x a client at the median and 0.75 to 1.19x from the 10th to the 90th percentile (it read 0.005x); not modelled: text laid out as a GUI enters a player's screen, and a chain of parts entering the Workspace (0.4x). Taking a child out of its parent's list (a `Parent` write, `Remove`, `Destroy`) pays 0.2 ns for each place a client's search for it passes (`cost::CHILD_SEARCHED`): a client looks at its last child first, then from the start of its list (the child order above), so a child 500,000 places into a list costs about 100 µs, a last child as much as where an earlier removal moved it, and 100,000 children taken out first to last, or their Folder destroyed, about what a client's 323 ms does (ree reads 1.05x a client at the median over 85 such rows; it read 0.027x).
- **Before the first frame:** a harness's or story's build, which ree does not time, takes no charges on the clock: `os.clock` reads the same across a call there (a loop that only reads it still drifts on, so it ends), while the script timeout still counts the call's work.

## Profiling internals (`src/profiler/`, `src/luau_profile.rs`, `src/boundary.rs`)

- **Instruction & cache profiling (`patches/luau/12-profiling.patch`):** Switches `luau_execute` to a single-step variant booking `lua_workcounters` deltas, engine charges, and cold/collector/dispatch/provenance splits (`lua_profilesplit`) per function, line, phase, and call-tree node (`version: 2`). C calls get their own call-site nodes; protected-call unwinds (`luaP_unwound`) keep nesting accurate without C++ exceptions. Inline cache sites (`GETGLOBAL`/`SETGLOBAL`/`GETTABLEKS`/`SETTABLEKS`/`NAMECALL`/`GETIMPORT`, plus fallback `*UDATAKS`) and `FASTCALL` builtins record per-node/per-phase hits, outcomes, `charged_work_us` (`first_touch_us` + `outcome_charged_us`, `presized_us`), `decline_charged_us` vs. `fast_equivalent_us`, and committed uncharged price ratios (`profiler/prices.rs`). `-O2`-inlined local functions are detected by line runs and counted separately.
- **Memory & heap snapshots:** `onallocate` + `lua_allocblock` + `lua_profilemark` track live allocations per stack; `lua_enumheap` walks all GC roots (including prototype metadata, open upvalues, and weak-table strings) to compute reachable heap, Cooper-Harvey-Kennedy dominators (retained sizes), BFS retainer paths, table array/hash utilization histograms, SCC nesting depths, and `ltable.cpp` `rehash` stacks—keeping uncollected garbage separate without forcing GC.
- **Timeline, issues & boundary:** `timeline.function_stats`, `timeline.issue_stats` (full-run peak/over-budget tracking independent of timeline capping), and over-budget `node_frames`/`site_frames`/`replacement_frames` drive `profile-view` issue pricing (exact vs. estimate vs. at-most vs. part bounds; deduplicated set-union totals; whole-code bounds for source edits except operand-preserving `string.byte(s)` and `string.sub(s, i)`; physical-frame boundary denominators excluding frame 0).
- **Hardware counters (`patches/luau/17-profile-calls.patch`, `src/profiler/hw/`):** Context-switch PMC traces from `ree-hw-counters` split cleanly on helper-thread yield switches (`hw::readings::split`). Adaptive call sampling (`every` tuned between 20 us and 1 ms for ~10k readings/s, 10 us floor / 7.5 us hysteresis, up to 64 recursive calls together, 2M slice cap) produces unbiased per-function counter estimates summing to the run total.
- **Host-time sampling (`src/luau_profile.rs`):** 1 ms ticker checked via atomic load at safepoints, engine steps, and C metamethods, weighted by run-thread CPU cycles (`QueryThreadCycleTime`), tracking `ccalls` per interpreter entry so C-call time isn't mis-attributed to `-O2`-inlined code. The ticker thread runs at time-critical priority on Windows: with every CPU busy, a late tick let engine work pass the booking points unbooked and the next Luau line took it.
- **Overhead & isolation:** When disabled, hooks cost a single thread-local read (~0.25 ns; `hw` call hooks run in a separate compiled `lvmexecute_profiled.cpp` copy at +0.0% overhead when off). When enabled, profiling allocates zero bytes on the Luau heap and produces byte-identical recordings.
- **Memory figures vs. Roblox:** `gcinfo()` and `collectgarbage("count")` return whole KB including uncollected garbage (baseline includes `ree`'s prelude/services; each Instance userdata is 48 bytes). `Stats:GetMemoryUsageMbForTag` is not emulated.

- **Workspace physics state (`services/mod.rs`, `world/joints.rs`; Studio 0.748, a playing client and its server alike: `workspace_physics_state.luau`, `unjoin_from_outsiders.luau`; `JoinToOutsiders` below):** `PGSIsEnabled()` is `true` and `GetPhysicsThrottling()` `100` (the share of real time physics runs at; ree's never falls behind), whatever the arguments; plugin code in Studio's edit DataModel reads the same (identity 5, the probe's calls run there by hand, not a capture). `UnjoinFromOutsiders(objects)` takes every active joint between a listed part and an unlisted one out of the DataModel (`Parent = nil`: the joint is not destroyed, keeps `Part0`/`Part1` and can be parented again, which links its parts up again), and the assemblies split. ## Content ids (`src/content_id.rs`)

How Studio 0.747's client reads a content id that names an asset (measured 2026-11-24 in playing clients with the asset network on; `tools/parity/probes/content_ids.luau` checks what is read before a fetch). Properties keep an id as written. Two readers:

- **Images and meshes (`content_id::asset`):** `rbxassetid://N&version=V` is version V of asset N, the spelling Roblox saves a pinned version in. The pairs after the first `&` are form-decoded and trimmed; `version` in any case takes an integer (sign, leading zeros, `0x` hex; 0 or less is the latest), and the first that is no integer ends the reading; a lower-case `id=M` names asset M; `assetversionid` and any `#` load nothing. Spaces around N are allowed. Nothing loads for `N/`, `N?version=V`, `Nabc`, an upper-case scheme, whitespace before the scheme, bare digits or a URL without a scheme. A web URL keeps ree's reading of its first `id=`, and its `version` pins one too. A pinned version downloads into `<state dir>/meshes/<id>-v<version>` (images: `images/`), never the latest's file, and `CreateEditableMeshAsync` raises `Failed to load mesh <id>` for an id of no known protocol.
- **Animations (`content_id::animation`; `LoadAnimation`, `GetKeyframeSequenceAsync`, `GetAnimationClipAsync`):** the leading digits after `rbxassetid://` (up to 19) name the asset, and what follows is never read, so every pinned spelling plays the latest version (asset 507766666 has 13 versions; `&version=1` played the 13th). An http(s) URL needs an `id=` whose value starts with a digit, and the asset is the leading digits after its *last* `=`, so `?id=N&version=V` asks for asset V, as the client does. An id the client cannot read raises its text from all three (`Invalid animation id '<error: unknown AssetId protocol>': ` and the others in `content_id.rs`), an empty one `LoadAnimation requires the asset id to not be empty`. `ContentProvider:PreloadAsync` calls back once for each Animation with an id, with that id and `Success` or `Failure` (an unreadable id, one with `#`, one not found); another instance item still gets its own text and `Success`.

## Animation (`src/animation/`)

Calibrated against Studio 0.747 (`src/animation/curve_golden/`):

- **Loading & latency:** Enabled by `animation::enable` (`--animations` dirs → `<state dir>/animations` → asset worker `asset` command; registered clips always work). An AnimationId is read as "Content ids" above says. First fetch of an asset resolves **0.45 s** later (tracks have `Length = 0` until loaded; `ContentProvider:PreloadAsync` awaits them; subsequent loads are instant). Missing IDs warn once.
- **Blending & posing:** Runs in play mode after `PreAnimation` and before `Stepped`. Priorities (`Action4` → `Core`) each claim `min(summed_weight, remaining)` (negative weights = 0), blending tracks by weight with remainder at rest. While any track steps, every rig `Motor6D`/`Bone` is written each step; when all tracks stop, joints retain their last pose. `Animator:StepAnimations(dt)` works in edit mode and raises a capability error in play mode.
- **Curves (`curve.rs`, `curve_golden/`):** `FloatCurveKey` / `RotationCurveKey` snap to `1/2400 s` ticks (`SetKeys` drops closer duplicates; `RotationCurve:SetKeys` raises `"Variant cast failed"` like Studio 0.747—use `InsertKey`). `FloatCurve:GetValueAtTime` matches Studio bit-for-bit in `f32` (including auto-tangent slope rules). `RotationCurve` interpolates shortest-arc slerp/Hermite within `2e-6 rad`. `EulerRotationCurve` / `Vector3Curve` cache `X`/`Y`/`Z` child channels by name-at-parenting rules (`channels.luau`, `arrivals.luau`). `MarkerCurve` enforces 64-byte marker strings and NUL-termination truncation on serialization (`markers.luau`). Curve data persists in hidden `ValuesAndTimes`.
- **Track stepping (580/580 golden lines exact):** `TimePosition` and `WeightCurrent` are `f32` (`WeightTarget = 0` until `Play`). Steps fire markers in `[start, end)` (keyframe markers before keyframe name). Passing `Length` (or `0` backward) fires end markers + `KeyframeReached("End")` (CurveAnimation only), `Stopped` (if unlooped), and `DidLoop` (whenever overshooting the end, even unlooped); unlooped tracks fade out over **0.3 s**. Negative speed starts at `Length`. `Ended` fires one step after fade reaches `<= 1e-5` (`Stop(0)` leaves `WeightCurrent` and pose intact; weights `< 0.001` don't pose; destroyed tracks keep playing; destroyed `Animator` stops tracks).
- **Pose sampling & packed sequences:** `CurveAnimation` samples at 30 Hz (`k / 30 s` in `f32`) and linearly interpolates between samples, applying Studio's polynomial acos rotation round-trip (translations bit-exact; rotations within `1e-6`). `KeyframeSequence` applies Studio's easing quirks (swapped `Cubic` In/Out, `Constant` In/Out/InOut) and packs evenly spaced all-`Linear` sequences onto a uniform time grid with 15-bit quantized translations (`1/32767` of max axis) and smallest-three quaternions (`sqrt(2)/32766`).
- **`FaceControls`:** Driven from `FaceControls` folders (`FloatCurve`s or `NumberPose`s) onto the rig's first `FaceControls` instance named `"FaceControls"`, blended by priority/weight and clamped to `0..1` (head mesh deformation itself is not simulated).
- **Providers (`rbxtemp://` and `active://`):** Content-addressed `rbxtemp://N` IDs deduplicate identical clips, strip non-`Archivable` descendants, and return one cached instance per ID (`GetKeyframeSequenceAsync` converts `CurveAnimation` at 30 Hz and strips attributes/tags; `GetAnimationClipAsync` preserves them). `active://N` IDs are tracked independently per provider (`LoadAnimation` reads `AnimationClipProvider`'s `active://` IDs and tracks live clip edits).

## PhysicsService and WorldRoot collision groups (`src/services/physics.rs`)

A registry per DataModel, and one per WorldModel, that remembers collision groups and which pairs collide. ree simulates no collisions (it has no rigid-body contacts): nothing reads the registries but scripts. Measured on a 0.747 client and server (`collision_groups.luau`, `collision_group_args.luau`, `loopback/collision_groups.luau`), WorldRoot's methods and the name warning on a 0.748 playing client and its server (`world_root_groups.luau`, `world_root_group_args.luau`, `world_model_groups.luau`, `world_model_group_places.luau`, `world_model_group_corners.luau`, `collision_group_warnings.luau`, `loopback/world_model_groups.luau`):

- **Groups & masks:** ids `0`–`31`, `Default` at `0` and always there; a new group takes the lowest free id (`GetMaxCollisionGroups` is `32`). `GetRegisteredCollisionGroups()` returns a new array of `{ name, mask }` in id order each call (the deprecated `GetCollisionGroups()` adds `id`); `mask` is a signed 32-bit int whose bit *i* means "collides with group *i*" (`-1` for all). `CollisionGroupSetCollidable` sets both groups' bits (`Default` and a group with itself included); `CollisionGroupsAreCollidable` is `true` when either name is unregistered. Unregistering frees the id and resets its bit in every mask; renaming keeps id and mask. `CollisionGroupCollidableChanged` never fires for scripts.
- **Names & errors:** byte-compared and case-sensitive. Register / Unregister / Rename / Create / Remove refuse `""` (`Collision group requires a valid name.`), `Default` (`Can not use/change the Default collision group.`) and more than 100 bytes (`Collision group name length cannot exceed 100 chars`). A 33rd group raises `Cannot register more than 32 collision groups in this world.` (checked before duplicates); re-registering, unregistering or renaming an unknown name, and renaming onto a registered one, do nothing. `CreateCollisionGroup` returns the id and refuses duplicates; `CollisionGroupSetCollidable` needs both names registered (`Both collision groups must be registered.`); `GetCollisionGroupId` / `GetCollisionGroupName` raise `Collision group not found.` / `The Collision group Id must be between 0 and 32`.
- **Argument casts (last argument first):** a name casts any value to text (`5` → `"5"`, `true` → `"true"`, a table → `"{}"`, `0.1` → `0.10000000000000000555`, a Vector3 with nine digits a component: `0.100000001, 0.333333343, 2`, measured on a 0.748 server: string_parameter_casts.luau), after the warning for a name that is neither a string nor a number (`argument #1 expects a string, but Vector3 was passed`; "String parameters" above); the collidable flag takes booleans, numbers (`0` is false) and `"true"` / `"false"` in any case; ids round half away from zero; part arguments must be `BasePart`s.
- **Sides:** a playing client may read but not change the registry (`This API can only be used on the server!`); a server and edit mode (ree's default `--mode edit`, Studio's edit DataModel by Roblox's documentation, not measured) may. A client also sees its server's groups: a loopback client gets the server's registry at its join and, after a server frame that changed it, once as the frame left it (as a property's changes in a frame arrive once); it works out its parts' ids again when a group's name changed, and a change of masks alone leaves them, as `CollisionGroupSetCollidable` does on the server. The parts it works out cost the client's work clock what a client spends on them (cost.rs `CLIENT_GROUP_PART`, `CLIENT_GROUP_CHANGED`, Studio 0.747, a loopback session's client timed frame by frame with 2,000 to 20,000 parts): 30 ns for each part it looks at and 1.86 µs more for each whose id changes, so 1,000 parts taking new ids cost about 1.9 ms; a snapshot of the groups the client already holds (the join's `Default` alone from a server that never touched its groups) looks at no part. Not matched: a change of masks alone costs a client about 45 ns a part, which ree does not charge.
- **WorldRoot:** the eight methods WorldRoot shares with PhysicsService (`RegisterCollisionGroup`, `UnregisterCollisionGroup`, `RenameCollisionGroup`, `CollisionGroupSetCollidable`, `CollisionGroupsAreCollidable`, `IsCollisionGroupRegistered`, `GetRegisteredCollisionGroups`, `GetMaxCollisionGroups`) work on the world they are called on. The Workspace's are PhysicsService's: one registry, the same rules and refusal. A `WorldModel` has a registry of its own, `Default` alone when made, with the same names, casts, limit and errors; `Clone` copies it, `Destroy` keeps it, and a server's reaches a client's copy of the WorldModel: a loopback client's with the copy (taken before its tree enters, and again when it comes back into the replicated containers), then once for each server frame that changed it, in the place of the frame's first change as the DataModel's are, its parts' ids worked out again under the Sides rule (when a group's name changed, or the groups are new to it); after a frame that changed the groups of a million WorldModels, a flush costs the host what it cost before it. A client may change it only while the WorldModel is outside the DataModel (in nil or under a parentless instance); in it (the Workspace, ReplicatedStorage, a ViewportFrame, the Camera) the four changes raise `This API can only be used on the server!` where the Workspace's do. With `UseWorkspaceCollisionGroups` true the methods still work on the WorldModel's own groups, and its first call that gets past the casts warns once (no stack): `<full name>: UseWorkspaceCollisionGroups is true, so this WorldModel's own collision groups are not the ones used for its simulation. If you meant to access or change the simulated groups, set UseWorkspaceCollisionGroups to false or edit them on the Workspace.` (a Clone warns again).
- **Parts:** `BasePart.CollisionGroup` takes any name, registered or not (`""` is ignored, longer names are cut to 100 bytes); `SetPartCollisionGroup` writes it the same way and `CollisionGroupContainsPart` compares it. For a part in the Workspace, `CollisionGroupId` is its group's id (`-1` when unregistered), set when the part enters the Workspace, when its name changes there, and for every placed part when groups are registered, renamed or removed (firing `Changed`); outside the Workspace it keeps its last value. A part in a WorldModel follows that world instead (its nearest WorldModel, while the WorldModel is in the DataModel, anywhere in it): its own groups, or the Workspace's while `UseWorkspaceCollisionGroups` is true. The Workspace's groups reach none of a WorldModel's parts, and its own reach them only while it uses them; a part entering a WorldModel (or a WorldModel entering the DataModel) takes its id from the WorldModel's own groups, firing `Changed`, then without `Changed` from the Workspace's if it uses those; a change of `UseWorkspaceCollisionGroups` works the ids out again with no `Changed`, over an id a script wrote; a part moved within its world keeps its id. ree starts this tracking once a run touches collision groups; before that a part keeps the id it was loaded with. A change that works the ids out again costs the work clock what a server spends on it (cost.rs `COLLISION_GROUP_PART`, `COLLISION_GROUP_CHANGED`, Studio 0.747): 1.7 ns for each part in the Workspace and 0.38 µs more for each whose id changes; a tree coming into the Workspace pays the same for the parts it brings. A `CollisionGroup` write that changes nothing (the name the part has, or `""`) costs what any write that changes nothing does, below WorldModels too, and `""` 1 µs more whatever the levels (cost.rs `COLLISION_GROUP_IGNORED`, Studio 0.747: 0.89 to 1.32 µs a write). The Workspace's other instances cost a server's change next to nothing (Studio 0.747: a register and an unregister 4.0–6.8 µs beside 100,000 Folders, 1.8–3.4 beside none), and ree looks at none of them: it takes the parts from the spatial queries' broadphase and the Terrain, and the parts whose ids change take them (firing `Changed`) in the order the Workspace's descendants are listed; that ordering walk costs ree's own price past its allowance (`QUERY_ORDER_STEP`, for parts whose paths meet only far up). The broadphase holds the parts of the Workspace's WorldModels too: the Workspace's change looks at each, at a part's price, and leaves it out. A WorldModel's own change costs the same on its parts (not those of a WorldModel inside it, as the Workspace's leaves out those in a WorldModel), and so do a change of `UseWorkspaceCollisionGroups` on the parts it works out again and a tree that comes into a WorldModel's world, or moves between worlds, on the parts that take their ids (both passes for the parts of a WorldModel that uses the Workspace's groups); none of these was measured apart from the Workspace's. A group change reads no WorldModel's own spatial index (`WorldIndex`, made at its world's first spatial query or physics step): ree finds its parts by walking its descendants, which costs each other instance it looks at what a recursive find costs for a node (cost.rs `FIND_NODE`, a price borrowed, not measured for a WorldModel), on a loopback client's copy too. Whether a WorldModel outside the Workspace is in the DataModel is looked for up its ancestors, which a method call, a part's `CollisionGroup` write and a change of `UseWorkspaceCollisionGroups` pay for as `IsDescendantOf` does (cost.rs `ANCESTOR_STEP`), once a call; a Parent write pays for the chains it walks already. Groups a place file saved are not loaded: a run starts with `Default` alone.

## Teams (`src/services/teams.rs`)

A player's `Team`, `TeamColor` and `Neutral`, the `Teams` service's teams, and the team a joining player gets. Measured in 0.747 play sessions (`teams.luau`, `loopback/team_join.luau`, `team_pick.luau`, `team_none.luau`, `team_absent.luau`, `team_links.luau`, three captures each; four clients joining one server for the spread):

- **Team follows the colour:** `Team` is `nil` while `Neutral` is `true`, else the first team among `Teams`' own children (child order) whose `TeamColor` is the player's, else `nil`. Each side works it out again when the player's `TeamColor` or `Neutral` changes, a team's `TeamColor` changes, or a team enters or leaves `Teams` (destroying one included): a player whose team leaves keeps its colour and `Neutral = false` with `Team = nil`, and gets the team back when it returns. A change fires the old team's `PlayerRemoved`, the new team's `PlayerAdded`, then the player's `Team` signals, after the signals of the write that caused it.
- **Writes:** writing `Team` writes `TeamColor` (the team's) and then `Neutral = false`, each firing its own signals, and the team follows from them (so a team whose colour an earlier team shares gives the earlier one); `nil` writes `Neutral = true`. A team outside `Teams` (destroyed or never parented too) raises `Setting Player.Team failed because team must be a child of the Teams service` and changes nothing; another instance raises `Expected Team got <ClassName> for Player.Team.`, another value `Unable to assign property Team. Team expected, got <type>`. `TeamColor` takes a `BrickColor`; `Neutral` any value, by truth.
- **Joining:** a player starts neutral (`Neutral = true`, `TeamColor = White`, `Team = nil`). On a server, a joining player is given, before the team's `PlayerAdded` and `Players.PlayerAdded` fire, the auto-assignable team in `Teams` with the fewest players, the first in child order among the fewest; a player counts on every team of its colour. With no auto-assignable team in `Teams` (none at all, only fixed ones, or one parented elsewhere) it stays neutral. Players already in keep their teams when teams are added or changed later.
- **Queries:** `Team:GetPlayers()` is every player in `Players` who is not neutral and has the team's colour (two teams of one colour both list it), in child order; a team outside `Teams` raises `Team:GetPlayers() failed because team must be a child of the Teams service`. `Teams:GetTeams()` is `Teams`' children that are teams, in child order.
- **Clients:** a loopback client receives `TeamColor` and `Neutral` and works its own `Team` out from its copies of the teams (`Player.Team` is not replicated), firing the same signals in the same order as the server. A client-only run's local player starts with the team its server would give the first player to join, without signals, as a real client finds it at its first line; in edit mode it stays neutral. A real client's first `ReplicatedFirst` script can see the colour before the teams arrive; ree has no staged loading, so its client sees the team at once. Known difference (`known-loopback.json`): ree fires a joining player's `Players.ChildAdded` before `PlayerAdded`, where Roblox fires it after.

## Localization (`src/services/localization.rs`)

`LocalizationTable`, `Translator` and `LocalizationService`'s translators as a playing client has them (measured in 0.747 play sessions, a client and a server alike: `localization_entries.luau`, `localization_templates.luau`, `localization_lookup.luau`, `localization_formats.luau`):

- **Entries:** `SetEntries` takes an array of dictionaries with string `Key`, `Source`, `Context` and `Example` and a `Values` dictionary of strings by locale, and refuses the whole call at the first bad entry with the client's messages (`entries was not an array.`, `Entry at index 2 was not a table.`, `Entry at index 1 had was missing "Values".` and the rest). An entry is named by its `Key`, or with no `Key` by its `Source` and `Context`: a second entry with a key raises, a second keyless one is dropped. Locale ids are kept lower case with `-`. Sources are templates and are checked when set. `GetEntries` lists entries grouped by `Source` (the groups in the order they were made; a group keeps its place when its entries go), each group by `Context`, then `Key`. The entry methods (`SetEntry`, `SetEntryValue`, `SetEntryContext`/`Key`/`Source`/`Example`, `RemoveEntry`, `RemoveEntryValue`, `RemoveKey`, `RemoveTargetLocale`, `GetString`) find entries the same way and, but for `SetEntryExample`, make missing ones; a change that would clash with another entry raises, one that leaves an entry with no key and no `Source` loses it.
- **Contents:** a table keeps its entries in `Contents` (hidden from scripts), the JSON `GetContents` returns; `SetContents` reads that JSON with the client's errors, and a `Clone` reads its copy the same way (it loses the examples, as a client's copy does). Entry writes fire no `Changed`.
- **Translators:** a new `Translator` instance each call (named `Instance`, its `Parent` locked, `LocaleId` read-only, `Clone` giving `nil`). A table's translator reads the table and the tables it is in, up to the first ancestor that is not a table; `LocalizationService`'s read the tables in the service that only tables hold, each table's own entries after those of the tables in it. Both read the tables as they are at each call. A table's translator does not keep its table alive: once the table is collected, `FormatByKey` and `Translate` raise `LocalizationTable no longer exists`.
- **`FormatByKey(key, args)`:** the first table with a translation of the key for the locale (the locale's own, its language's alone, a paired locale's such as `es-mx` for `es-es`, then another locale of its language; Chinese only between its own four regions), or whose source locale has the locale's language and a `Source` for the key; else `Key <key> not found for locale <locale>`. The text's `{1}` parameters read an array, `{name}` ones a dictionary; numbers are written with two decimals, and the formats `int`, `fixed`, `num` (the locale's separators), `hex`, `HEX`, `datetime`, `iso8601`, `shortdatetime`, `shortdate`, `shorttime` (the host's local time and the locale's pattern) and `translate` are the client's, with its errors.
- **`Translate(context, text)`:** the translation of the entry with that `Source` whose `Context` best fits the context instance's full name (most trailing names agreeing, ASCII case aside, then in case; the last of the best), else the text itself.
- **`LocalizationService`:** `RobloxLocaleId` and `SystemLocaleId` are `en-us` (or the client profile's); `GetTranslatorForPlayer` gives the player's `LocaleId`; `GetTranslatorForPlayerAsync` needs a `GameId` (`Publishing the game is required to use GetTranslatorForPlayerAsync API.`); `GetTranslatorForLocaleAsync` takes a locale of two characters or more and answers at once (a client waits on the web for the experience's table); `GetTableEntries` lists the service's tables' entries and an empty list for the experience's own table. Roblox's own members raise the capability error.
- **Work clock:** each call is priced as the client spends it (cost.rs `LOCALIZATION_*` and `method`): `SetEntries` by its entries and values, `GetEntries` likewise, `FormatByKey` by its text, parameters and numbers, `Translate` and the rest per call.

## Settings roots (`src/services/settings.rs`)

`settings()` (`GlobalSettings`) and `UserSettings()` (`UserSettings`, named `GlobalBasicSettings`) are instance roots outside the DataModel, each a `GenericSettings`. Measured in a Studio 0.747 playing client and server (`global_settings.luau` at script identity 2; `global_settings_tree.luau` and `global_settings_services.luau` at identity 4, the command bar's, which has the Plugin capability):

- **Who gets it:** a game script's call raises `The current thread cannot call 'settings' (lacking capability Plugin)` (no position, any arguments), so every play run raises it. In edit mode, where a plugin's code runs, `settings()` is one `GlobalSettings` object named `Global Settings`, made on the first call (a run that never calls it numbers its instances as before).
- **Tree:** eight services from the start, in order: `GameSettings` "Game Options", `LuaSettings` "Lua", `DebugSettings` "Diagnostics", `PhysicsSettings` "Physics", `Studio` "Studio", `NetworkSettings` "Network", `RenderSettings` "Rendering", `TaskScheduler` "Task Scheduler". Names index them, full names start below the root, and missing members raise `X is not a valid member of GlobalSettings "Global Settings"`.
- **Values:** the measuring client's settings (`QualityLevel` and `EditQualityLevel` `Automatic`, which follow the user's choice; `MeshCacheSize` `33554432`; `TickCountPreciseOverride` `Precise`; `AllowSleep` `true`; ...). Live readings of the process and machine (instance, job and player counts, free and total memory, scheduler rates, thread pool size, `RobloxVersion`) report `missing` and answer the measuring client's reading; `Studio`'s settings report `missing`; `GetFFlag`/`GetFVariable` report `missing` and answer `nil`. `RenderSettings:GetMaxQualityLevel()` is `22`.
- **Writes:** `RenderSettings` writes fire no `Changed`; the other services' do. `GameSettings.VideoCaptureEnabled` and every settings service's `Name` drop writes; `NetworkSettings.HttpProxyEnabled`/`HttpProxyURL` refuse them and `PhysicsSettings`' debug-drawing settings refuse reads and writes (`lacking capability RobloxScript`).
- **GetService:** a root answers its own services; the other root's raise `Invalid parent for Service. <Class> cannot be parented to <root name> .` (a game script gets `nil` for `GameSettings`, `DebugSettings`, `PhysicsSettings`, `RenderSettings`, `Studio`); 109 DataModel services raise `Not allowed to add that under settings`, the rest are `nil`, and nothing is created. `game:GetService` answers the settings services the same way (with the place's name) and `nil` for `GlobalSettings`, `UserSettings`, `GenericSettings`, `ServiceProvider`.
- **Locked tree:** services keep their parent, refusing every write by class (`Cannot change Parent of type RenderSettings`, the parent they have too) and `Destroy` (`The Parent property of Lua is locked`); a root's `Parent` raises `The current thread cannot set 'settings parent' (lacking capability RobloxScript)` (`'UserSettings parent'`), but `Parent = nil`, the parent it has, is no change (Studio 0.748, edit and a playing client) and the root set to itself raises `Attempt to set Global Settings as its own parent` (Studio 0.747, `parent_locks_settings.luau`); nothing can be added below (`Not allowed to add that under settings`); neither roots nor services clone.

## Client profile (`src/client_profile.rs`)

Everything about the emulated client and its player comes from one `ClientProfile` (`Options::profile`), so no two readers can disagree. Every field is optional: a field left unset keeps the engine's own answer, and the empty profile (the `default` preset) leaves every output as it was before profiles. The format is JSON (`data/client-profile.schema.json`); the command line takes it as `--client-profile` (cli.md, "Client profile"). A host builds one with `ClientProfile::from_json` / `ClientProfile::parse`, or sets its typed fields (`options.profile.device.kind = Some(DeviceKind::Touch)`), and reads effective values through its accessors (`profile.device.viewport()`, `profile.identity.user_id()`, ...).

- **Whose answers:** what the profile says about ownership, policy, groups, friends and the country is said of its player, the `Player` whose `UserId` is the profile's (`identity.userId`, else 1): the local player, or on a server the player a harness adds with that id and a loopback client's `Player`. Any other player gets the engine's own answers. The name lookups find the profile's player by its id on a server as on its client.
- **What is measured:** the shapes of these answers without a profile are the engine's measured ones. With a profile, each answer takes the profile's value as given: `PreferredInput` follows a touch device or a gamepad (`Touch`, `Gamepad`) as Roblox's documentation describes and Studio 0.747 clients with a phone's and a gamepad's input read (a run with `--device touch`, `phone` or `gamepad` reads it so too, where it read `KeyboardAndMouse` before the profile); `IsTenFootInterface`, the policy table under other policies, ownership, groups, friends and the rest are taken from the profile and are not measured. Members that are not emulated without a profile (`PlayerOwnsAssetAsync`, `GetUserSubscriptionStatusAsync`, `CheckUserBadgesAsync`) answer once the profile sets what they read, in the shapes Roblox's documentation gives (`{ IsSubscribed, IsRenewing }`, the owned badge ids in their order); a listed subscription renews.
- **Layers:** profiles merge as a JSON Merge Patch (RFC 7396), each over the ones before it: objects key by key, lists and other values replaced whole, `null` removing a field (back to the engine's answer). The order: `REE_CLIENT_PROFILE`, the shorthand variables (`RUR_PLAYER`, `RUR_PLAYER_ID`, `RUR_PLAYER_DISPLAY`, `RUR_PLACE_ID`, `RUR_CAMERA`, `REE_DEVICE`), the command line's `--client-profile` layers in their order, then its flags (`--player`, `--device`, `--viewport`, `--camera`, `--place-id`, `--streaming`). A preset is a default the flags go over; a flag that sets a field one of the command line's `--client-profile` files or inline JSON sets to another value is refused, naming both. Fields still unset then take the project's place id and streaming radius (`rur.json`).
- **Presets:** `default` (nothing set), `desktop-us`, `phone`, `console`, `locale-de`, `china-policy`, `premium-owner`, `new-account` (`data/client-profiles/*.json`). Their values are configuration, not measurements.
- **A running harness:** `Context.ClientProfile()` reads the profile, and `Context.SetClientProfile(patch)` merges a patch over it for what the engine reads at call time (`policy`, `ownership`, `social`, `localization.countryRegion`) on the side it runs on; a patch touching what the run set up at its start, or a `null` removing it, is refused with the field named. `Context.Null` removes a field in a table patch, and an empty table is an empty object (an empty list where the format has one).
- **Store limits:** seeded data keeps to what the stores take: a data store's names, scopes and keys 1 to 50 bytes and values up to 4 MB as JSON; a memory store's keys 1 to 128 bytes and items up to 32 KB.
- **Traced and keyed:** a run started with a profile layer has `clientProfile` (`sources`, `digest`, `profile`, the data section by its stores' names and keys only) in its summary. `--client-profile` is part of a prepared run's key, a profile file a run read is checked like any other file it read, and `REE_CLIENT_PROFILE` (its files made absolute) is part of the service key.

## Server and edit run contexts (`src/lua/server.luau`, `src/lua/loading.rs`)

- **Server (`--run-context server`, requires `--mode play`, forbids `--player`):** `IsServer`/`IsStudio`/`IsRunning = true`, `IsClient`/`IsRunMode = false`, `IsEdit` forbidden to game scripts (`--studio false` flips `IsStudio`). Empty `Players`, no rendering (`RenderStepped` errors; `PreRender`/`BindToRenderStep` bind silently), tweens step before `Heartbeat`. Includes in-memory `DataStoreService` (versions, keys, `OrderedDataStore`), `MemoryStoreService` (sorted/hash maps, queues), both empty or with the client profile's `data`, `MessagingService`, and `EncodingService` (Zstd, Base64 and the `HashAlgorithm` digests of `ComputeBufferHash` / `ComputeStringHash`, also available on clients). Stored and published values are converted first, as an event copies a table: past the Lua stack they raise `Max lua stack size reached` (arrays nested 300 deep for `SetAsync`/`AddAsync`, 295 for an `UpdateAsync` transform's result, 297 for `PublishAsync`; dictionaries half as deep) and a table inside itself `tables cannot be cyclic`, before anything they cannot hold is reported. The conversion writes a table out each time it appears (a 0.747 server: one table of 1,000 numbers held 8,000 times took `SetAsync` 0.4 s, and a cycle after all of it still raised first): ree counts a value's JSON length as it walks, copies nothing more once it passes what the store takes (4 MB for a data store, 32 KB for a memory store, 1 kB for a message, 300 bytes of metadata: Roblox's documented limits, as a local test server enforces none), and goes on looking for the errors that win over the size up to its guard on a copy (4,194,304 values), past which the store raises its size error. `FireClient`/`FireAllClients` are no-ops; `InvokeClient` yields until the player leaves (loopback servers reach their paired client; see below).
- **Edit (`--mode edit --run-context edit`):** `IsClient` and `IsServer` both `true`, `EncodingService` enabled, `Players.LocalPlayer = nil` unless the command line names a player (`--player`, or `identity.name` in a `--client-profile`). The fast-flag methods and `GuiService:GetResolutionScale` raise as for a game script (see "Members a game script may not use"); `settings()` answers, as for a plugin (see "Settings roots").

- **Players leaving (`src/services/players.rs`):** however a player leaves `Players` (`Kick`, a script setting its `Parent` or destroying it, a loopback client's `Context.Leave()`), a server fires, in this order: `Players.DescendantRemoving` of the player; when its `Character` is an instance, `CharacterRemoving` with it, the character leaving its parent (wherever it is) and `Character` set to `nil`; the player's `PlayerGui` destroyed (its `Destroying`, then its removal events); the rest of the player's `DescendantRemoving` events (`StarterGear`, then `Backpack`, the order a joining player gets them in; both stay in the player until it is destroyed); `PlayerRemoving`; then the player's `ChildRemoved`, `AncestryChanged` and `Changed("Parent")`. The departed player's `Parent` is locked. Unless the place sets `Workspace.PlayerCharacterDestroyBehavior` to `Disabled`, the character is destroyed one second after the leave (wherever it is then) and the Player five seconds after, where `task.delay` threads resume, charged to no script; with `Disabled` both stay unparented. A script's own leave pays the character's removal what that reparent costs; the `PlayerGui`'s destroy, `Kick`'s leave, a loopback client's and the destroys cost scripts nothing. An `InvokeClient` waiting on the player raises `Player <name> disconnected during remote call to <the remote's full name>`. A client run's harness player leaving shows a client's order instead: the character's removal, then `CharacterRemoving` and `Character`'s change, then the player's events; nothing is destroyed later. Measured in 0.747 play sessions of one server and up to four clients (`loopback/player_leaving.luau`, three captures).
- **`Kick` (`src/lua/server.luau`, `src/services/players.rs`):** the player stays about a second (its `Parent`, `Character` and place in `GetPlayers` as they were, nothing fired at the call, a second `Kick` changing nothing, `FireClient` still reaching its client). The server's own timer closes the player's connection at the first frame that starts more than a second after the call (the client hears nothing sent from that frame on), and the player leaves at the next frame's network step, charged to no script: 62 frames (1.033 s) at 60 Hz. Measured on a server whose client runs in a process of its own: 61 to 62 frames at 60 Hz, 32 at 30 Hz, 26 with 40 ms frames, the same with the client busy for seconds or reading its replication a second late, so a player with no client leaves after the same delay; a client in the server's own process (Studio's Play) left a frame sooner. A `Destroy` or `Parent` write during the delay is a leave at once.
- **A script's `Character` write (`src/services/players.rs`):** on a server a write that changes it fires `CharacterRemoving` with the old character when it held one (destroyed or parentless too), takes the old one out of its parent in the writing thread, then fires `CharacterAdded` with the new one when it is an instance, then `Changed` and the property's signal; the old character is destroyed a second on as a departed player's is (`Disabled` keeps it unparented), and the same value fires nothing. A client (the player's own and the others) sees the old character's removal as the server's own change, then `CharacterRemoving`, `CharacterAdded` and `Changed`; a client script's own write fires the same three and moves nothing. The script pays the write and the old character's reparent. A server's write of an instance is also a spawn: before `CharacterAdded` the player's `Backpack` is destroyed and a new one holds copies of `StarterPack`'s children, then of its `StarterGear`'s; when the new character is in the `DataModel`, between `CharacterAdded` and `Changed` the `PlayerGui`'s guis that reset on spawn (any but a `LayerCollector` whose `ResetOnSpawn` is false) are destroyed and `StarterGui`'s copied in again, all of them on the player's first spawn (`loopback/character_respawn.luau`). `LoadCharacter` is not emulated. Measured in 0.747 play sessions (`loopback/character_write.luau`, three captures).

### Loopback run context (`--run-context loopback`, `src/loopback`)

Runs a paired server and client (`RunContext::Server` + `RunContext::Client`) on one thread with two `DataModel`s and two Luau VMs. Every frame steps the server first, then the client with identical `dt`. Calibrated against two-process Studio 0.747 loopback captures (`node tools/parity/run.mjs --loopback`, `tools/parity/probes/loopback/`, 3 captures per probe).

- **Startup & join lifecycle:** The server mounts the project and runs `Server` up to its first yield, then the player (`--player`) joins before frame 1 and `Client` starts (client runs `Engine.Start` only, interpreting engine Luau). Use `Context.HoldJoin()` / `Context.Join()` on the server to defer the join to the end of a chosen frame (client clocks start at join); `Context.Leave()` removes the player at the next frame boundary (a leave as any player's on the server, its character with it; client stops stepping, pending server `InvokeClient` calls raise). When the server takes the client's player out (a `Parent` write, `Destroy` or `Kick`), the client is cut off instead: a `Parent` write's or `Destroy`'s frame still arrives, its own leave in it (`CharacterRemoving`, `PlayerRemoving` of its own player, its removal events), `Kick`'s leave never (nothing arrives from its timer's frame on); then nothing passes either way (`FireServer` sends nothing, an `InvokeServer` never returns, the server's `InvokeClient` calls on it raise), while the client steps on, its scripts, frames and output running as a real client's do with no server, until the run ends as ever (`loopback/own_leave.luau`, three captures; a real server whose connection had been idle sometimes dropped that last frame, never while it sent every frame). Both sides read `Context.Side`; server reads `Context.Player` (supports `Context.SetJoinData`). Without `--harness`, each side boots its own enabled place scripts once (server `Legacy` under `Workspace`/`ServerScriptService` and `Server` outside `ServerStorage`; client `StarterPlayerScripts` copied into `PlayerScripts`, `LocalScript`s in `ReplicatedFirst`/player containers, and `Client` scripts outside `ServerStorage`/Starter containers).
- **Initial replication:** The server creates the player (`Backpack`, `PlayerGui`, `StarterGear`), fires `PlayerAdded`, and pairs it with the client's `LocalPlayer` (plus `PlayerScripts`). The client receives a silent copy (no events fired), each list in the order its children came into the replicated containers (`loopback/replicate.rs` `Ranks`, `tools/parity/probes/loopback/child_order.luau`: a child taken out there closes its gap, one that left the containers and came back is last, one moved to another list in them and back keeps its place, a tree that came in brings the order it had; the server itself keeps its lists as a client does, and its changes after the join leave the client's lists in its order), of children across the 19 replicated services (`Workspace`, `ReplicatedStorage`, `ReplicatedFirst`, `Lighting`, `Players`, `StarterGui`, `StarterPack`, `StarterPlayer`, `Teams`, `SoundService`, `Chat`, `TextChatService`, `LocalizationService`, `MaterialService`, `TestService`, `InsertService`, `MarketplaceService`, `ProximityPromptService`, `PolicyService`)—never `ServerStorage`, `ServerScriptService`, server `Camera`, or `RURFixtures`. Every property replicates except `LocalTransparencyModifier`, `Workspace.CurrentCamera` and `Player.Team` (each side works it out: see "Teams"), along with attributes and tags (unreplicated instance refs become `nil`; server `Script`s replicate without `Source`, while `Client`-context `Script`s, `LocalScript`s, and `ModuleScript`s keep `Source`).
- **Lazy Studio-only instances:** The join copies only what the server has made. Studio-only placeholders from the place's hierarchy snapshot are made on each side by its own scripts' lookups: a copy keeps its original's snapshot node and whether its Studio children exist, and the client makes them when it looks, as a plain client run does. The server's and client's instances of one snapshot node pair when a message first names one (a write, a remote argument, the remote itself), by the instance each was made under and the node (`src/loopback/lazy.rs`); a server instance made this way under a sent one replicates from then on. Lazily imported plans (which only the server can make) are made on the server at the join and copied. Manifest bundles stay lazy too (outside a world, whose walks and recorder read it whole: a bundle waiting in the Workspace or a WorldModel is imported at the join and copied): the join copies a waiting bundle's placeholder (or the folder its members go into) as it is, and only the server imports a bundle, when either side first finds, touches or looks inside it (`lazy::import_on_server`); the client's copy then takes what the import made at once, with no events (`lazy::bundle_imported`, `replicate::copy_import`; only what the import made, and a copy still on its way in a tree takes it when the tree arrives), so the client finds the bundle as a plain client run would, and the server's later changes to it replicate as any other's. A subtree holding waiting bundles that enters a world imports them first, on either side. A bundle nothing looked at is never fetched or made on either side. Neither side makes what only the other looked at.
- **Incremental replication & timing:** Post-join server changes in replicated containers (excluding `ReplicatedFirst`) flush at frame end in first-change order: new subtrees arrive whole (`ChildAdded`, no `Changed`), repeated writes coalesce (reverting produces no `Changed`), unparenting keeps client identity with `Parent = nil`, destroys fire `Destroying`/`ChildRemoved`/`AncestryChanged`, physics moves omit `Changed`. Client writes stay local until overwritten by the server. One ordered stream each way delivers at the receiver's next frame start (`--latency <frames>`, default `1`) at the receive point (after legacy `wait()` resumptions, before `PreAnimation`): replication and remote events queue deferred, while `RemoteFunction` callbacks and answers execute immediately at receive.
- **Remotes & queues:** `FireServer`/`FireClient`/`FireAllClients` snapshot args at call time (numbers with subnormals as `0`, byte-exact strings/buffers, datatypes, Axes, Faces, PathWaypoint, SecurityCapabilities and the sequence keypoints, mapped instances or `nil`, InstanceHandles as handles of the receiver's copy or of none, functions/threads/Enums/signals/curve keys/Path2DControlPoints/params objects/SharedTables as `nil`, a key's failing `__tostring` raised at the sender, Bindable-style table copies leaving holes for unmapped values; nesting counted as for Bindables from the call's frame: `FireServer`/`FireAllClients` arrays 299 deep and dictionaries 150, `FireClient` 298 and 149, one level less per further argument, a callback's results 300, past that `Max lua stack size reached`; a copy past ree's guard of 4,194,304 values raises at the sender, see "Tables copied once per place"). Reliable events preserve order and carry any size (1,000,000 values, 9 MB, each way); `UnreliableRemoteEvent` arrives after reliable events and drops payloads > 1,000 encoded bytes with Roblox's warning, which gives the whole payload's excess (`Payload went over by: 9002003 bytes` for a table of 1,000 numbers held 1,000 times; without buffer compression). Unlistened events queue up to **256** messages for the first listener, dropping extras with Roblox's queue-exhausted error logged at powers of 2 (`1, 2, 4, ...`). Calling wrong-side methods or connecting wrong-side events raises client error strings (parentless remotes silently no-op). `RemoteFunction` callbacks run on their own thread, preserve multiple/nil returns, forward errors with script/line (`error(x, 0)` strips location; tables become `""`), log an error raised before the callback first yields on the callback's side as an uncaught error is (not one after a yield), support nested/out-of-order calls, and raise on `Context.Leave()`.
- **Output, recording & limits:** Each side keeps its own `RunService`, work clock, script timeout (3rd timeout on either side aborts), and RNG sequence. Output lines merge in chronological order tagged with `"side": "server"|"client"`; `@done` on either side stops the run; `summary.loopback` logs latency, join frame, message counts, and replication stats; `ree record` captures the client world (`--record-side server` captures the server); `ree serve` runs loopback jobs cold.
- **Speed:** The client interprets engine Luau (loaded from the process's single compile); a module or harness both sides load compiles once per run (`lua::modules::share_compiled_modules`: the client loads the bytecode of the server's compile and runs its own copy). Tables cross through Luau's C API (`src/loopback/copier.rs`, same results as the typed copier); a message's table or buffer is kept once and each handler rebuilds its own. A replicated instance arrives as one property vector in name order, as `Clone` copies one. An idle pair frame costs its two engines' frames plus a few compares and allocates nothing of its own (`tests/alloc_counts.rs`); plain runs register none of the pair's hooks. `cargo test --release --test loopback_bench -- --ignored --nocapture` prints each cost against its target (`tools/bench/loopback/work.luau`).
- **Known differences & omissions (`tools/parity/known-loopback.json`):** `ree` sends exact CFrame rotations (vs. ~`1e-5` wire rounding), an instance moved out of its parent and back in one server frame arrives as where it ends (a real client sees both moves), `InvokeServer` after `Heartbeat:Wait()` returns 1 frame sooner, and server/client `GetServerTimeNow` align at frame start. Not emulated: multiple clients, characters/Humanoids, client network ownership/replication outside remotes, workspace streaming, `ReplicatedFirst` staged loading, packet loss/reordering/throttling, prepared service loopback jobs, and cross-server `MessagingService`.
- **Runtime code loading (Studio 0.747, `loadstring.luau`, `loadmodule.luau`, `core_services.luau`):**
  - `loadstring(src, chunk?)` raises `loadstring() is not available` unless enabled on a server via `ServerScriptService.LoadStringEnabled` or `--load-string`. Truncates at first NUL byte, inherits caller env (`setfenv` overrides per function), returns `nil, err` on syntax error.
  - `debug.loadmodule(module)` requires `--load-module` (`FFlagEnableLoadModule`); compiles `module.Source` into a fresh `function, nil, cleanup` isolated from `require` cache (JSON modules return a fresh decoder closure).
  - `getfenv(0)` and `getfenv` on engine functions walk the stack to return the calling script's environment (`patches/luau/18-script-thread-globals.patch`).
  - `game:GetService` / `FindService` return `nil` for Roblox-internal services (`CoreScriptSyncService`, `CorePackages`, `RobloxReplicatedStorage`, `PluginGuiService`, `RobloxPluginGuiService`, `AppStorageService`, `CSGDictionaryService`), while allowing `CoreGui`, `StudioService`, and `ScriptEditorService` (identity 4 behavior). `ScriptContext` has name `"Script Context"`.

## Output and `LogService`

- `LogService:GetLogHistory()` returns a fresh oldest-first array of `{ message, messageType, timestamp }` (wall-clock Unix seconds), recording `print`, `warn`, errors, and `LogService` calls immediately up to an emulator cap of **10,000** entries (`logservice.luau`).
- `LogService.MessageOut` fires after `Heartbeat` + deferred flush with `(text, messageType, contextCopy)` (messages emitted inside a `MessageOut` handler do not re-trigger `MessageOut`). Script errors include `Stack Begin` / `Stack End` lines.
- `LogService:Output`/`Info`/`Warn`/`Error`/`Log` take a message that is not a string as a client does: a number as `%.20g` writes it (`0.1` → `0.10000000000000000555`, `1e-310` → `9.9999999999999694493e-311`, NaN and the infinities `NAN`, `INF`, `-INF`), and anything else after a warning (`argument #1 expects a string, but boolean was passed`; `Log`'s message is argument #2, so its warning says `argument #2`, not measured): a Vector3 with nine digits a component (`0.100000001, 0.333333343, 2`; numbers and Vector3s: Studio 0.748 on a playing client and a server, string_parameter_casts.luau), and a table `"{}"`, an Instance `"Instance"`, a function `"function"`, an Enum `"nil"` (the warning and the rest: Studio 0.747, logservice_methods.luau), as any string parameter reads them ("String parameters" above, `convert::string_param`). They interpolate `{key}` placeholders (`{{`/`}}` escape), sanitize context copies (functions → `"<function>"`, instances → full name; mixed-key tables stringify non-primitives), and `Error` throws a formatted table with `{ message, template, context, stack }`.

## Known limitations

- `ImageLabel`/`ImageButton.IsLoaded`, `Sound.IsLoaded` (`TimeLength = 1`), and `DataModel:IsLoaded()` immediately return `true` without fetching assets.
- No rigid-body collisions, physics constraints, body movers, particle simulation, or default character `Animate` scripts (`PhysicsService`'s collision groups are a registry scripts read and write; nothing collides).
- No Humanoid simulation: no state machine, health or death (`TakeDamage`, `ChangeState`, `MoveTo`, `GetState`, and the `HealthChanged`/`Died` a `Health` write would fire report `missing`; `Health` is stored as written).
- All Luau HTTP requests are disabled.
- `ReflectionService` `Permits` holds no `SecurityCapabilities` (a frozen table reporting `missing` on access), and a `Security` filter reports `missing` and filters nothing; `GetPropertiesOfClass`, `GetMethodsOfClass`, and `GetEventsOfClass` are unimplemented.
- Subnormal numbers flush to zero only on x86-64 (the float mode above); an AArch64 or WebAssembly build keeps them.
- Primary development platform is Windows (Linux/macOS are built and smoke-tested in CI; off-Windows `ree serve` cannot detect stale dead PIDs via `alive()`, and memory checks use `/proc/meminfo` on Linux only).

## Compiled-in data files

- **`data/reflection.json`:** Public Studio API dump (`version: 0.747.0.7471481`, generated by `tools/dump-reflection.luau`, diffed with `tools/reflection-diff.mjs`), merged over `rbx_reflection_database` (legacy properties retained in `reflection.rs` `PROPERTY_SUPPLEMENT`). Powers `ReflectionService:GetClasses` / `GetClass` (`IsA` / `ExcludeDisplay` filters). For each class it records its superclass, `serialized`, `permits` and `display` (Category, DeprecationMessage) and the defaults of a new instance; for each property its type (`script`, `engine`, `enum`, and `instance`, the class an Instance type names), `serialized`, `permits` and `display`; for each method its parameters (name, type and the encoded `DefaultValue` as `default`), `returns`, `permits` and `display`; for each event its parameters, `permits` (`Listen`) and `display`; and each enum's items. Scripts see none of the member data beyond names; the Rust API reads it ([api.md](api.md#class-member-and-enum-metadata)). Reflects 0.747 quirks (`Spring`/`Bezier` easing rejected by `TweenInfo`/`TweenService`/GUI tweens; GUI tweens require DataModel ancestry; Camera orthographic writes ignored; `Capsule` treated as box; `EditableImage` unsupported combine/alpha errors; `ParticleEmitter.TimeScale` clamped `0..1`; `PluginOrOpenCloud` capability checks on streaming settings).
- **`data/text-advances.json` & `data/fredoka-sizes.json`:** Studio-measured glyph advance/kerning tables (no font files shipped).
- **`data/text-faces.json`:** For each weight and style of the families `Enum.Font` names, the `Enum.Font` face `GetTextBoundsAsync` measures it as (`same`), or the nearest one when it is a face of its own (`near`). Measured in a playing client by `tools/text-faces.mjs`, which runs `tools/text-faces.luau` through the parity capture command.
- **`data/font-enums.json`:** `Enum.Font` to `rbxasset://fonts/families/*.json` mapping.
- **`data/unicode-normalization.rs`:** Canonical decompositions and primary composites from the Unicode Character Database 12.1.0 (`UnicodeData.txt`, `CompositionExclusions.txt`), generated by `tools/unicode-normalization.mjs`, which downloads the pinned files and checks their SHA-256 (`--check` proves the committed table is what they make). It packs each decomposition into a `u64` and each composite into a `u16` index into that list (18,360 bytes) and is read by binary search. Unicode License V3 (`licenses/Unicode-3.0.txt`).

## Environment variables and host vs. standalone modes

No environment variable listed here carries credentials; `ree serve` stores only an unkeyed 64-bit hash of the environment (checkout/library hosts hash `RUR_*`, `REE_*`, `ROR_*`, and `LOCALAPPDATA`; standalone binaries hash the entire normalized worker environment).

- **`RUR_*` (shared with `rur`):** `RUR_STATE_DIR`, `RUR_CACHE_DIR`, `RUR_VERBOSE`, `RUR_ENGINE_TIMINGS`, `RUR_ENGINE_DUMP`, `RUR_EPOCH`, `RUR_CLOCK`, `RUR_CAMERA`, `RUR_PLACE_ID`, `RUR_PLAYER`, `RUR_PLAYER_ID`, `RUR_PLAYER_DISPLAY`, `RUR_ROTATION_CLIPPING` (the camera, place id and player variables write fields of the client profile), `RUR_PROFILE_CALLBACKS`, `RUR_LUAU_PROFILE`, `RUR_LUAU_PROFILE_CLOCK`, `RUR_LUAU_PROFILE_UNIT`, `RUR_LUAU_ALLOC_PROFILE`, `RUR_LUAU_ALLOC_STEP`, `RUR_BOUNDARY_PROFILE`, `RUR_CHARGE_TALLY`.
- **`REE_*`:** `REE_SCRIPT_TIMEOUT`, `REE_MAX_SCRIPT_TIMEOUTS`, `REE_MAX_WALL_SECONDS`, `REE_PARENT_WATCH`, `REE_SERVE_WORKERS`, `REE_FROZEN_CLOCK`, `REE_TIMING_CHECK`, `REE_RANDOM_SEED`, `REE_WORK_COUNTERS`, `REE_HASH_SEED`, `REE_HASH_ADDRESS`, `REE_LOCALIZED_PLACES`, `REE_MATCH_PLACES`, `REE_CLIENT_PROFILE` (the default client profile), `REE_DEVICE`, `REE_ASSET_WORKER`, `REE_ASSET_WORKER_ARGS`, `REE_PROFILE`, `REE_PROFILE_OUT`, `REE_PROFILE_COUNTERS`, `REE_HW_COUNTERS`, `REE_HW_PIN`, `REE_LUAU_FLAGS`, `REE_VIEW_COLOR`, `REE_VIEW_BLESS`.
- **Runtime/allocator:** `RAYON_NUM_THREADS`, `MIMALLOC_EAGER_COMMIT`, `MIMALLOC_PURGE_DELAY`.

### Host mode vs. standalone CLI mode

- **Library hosts** (never call `init_binary`): `default_repo()` finds the nearest ancestor `Cargo.lock` above the unresolved launch path or executable (or `.`); `state_dir(repo)` resolves `RUR_STATE_DIR` → `RUR_CACHE_DIR` → `<repo>/.cache`.
- **`ree` binary** (calls `init_binary` / `init_binary_exe` at startup): runs in checkout mode only if an ancestor directory of the unresolved launch path or executable has `Cargo.lock` beside a `Cargo.toml` for package `roblox-engine-emulator` (so builds reached through a symlinked or junctioned `target` directory keep checkout mode directly and across `ree serve --source`). Otherwise it locks into **standalone mode** for its entire lifetime (`is_standalone` = true): `--repo` is input-only, state resolves `RUR_STATE_DIR` → `RUR_CACHE_DIR` → per-user `ree` cache (`serve --state-dir` takes precedence; fails before writing if no cache dir exists), unnamed outputs write under `<state dir>` (`ree-profile`, `ree-boundary.json`, `what-if/<stem>`, `output/`), missing-worker errors report the checked executable path(s) and standalone reason, and standalone service clients absolutize `--frame-times` and known env paths before dispatch.
